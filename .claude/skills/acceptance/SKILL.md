# 受け入れテストの司会

**司会はあなた（AI エージェント）が務める。** 質問と選択はこの会話欄で行い、
[`tests/acceptance/run-acceptance.ps1`](../../../tests/acceptance/run-acceptance.ps1)
は道具として呼ぶだけ（[ADR 0070](../../../docs/v0.8/decisions/0070-agent-led-acceptance.md)）。
スクリプトは何も聞いてこない。

役割はこう分かれている。

- **あなた** — 環境を作る、項目を読み上げる、報告を 4 値に分類する、記録の文を書く、書き戻す、片付ける
- **オーナー** — **実キーボードで打ち、見えたことを自分の言葉で言う**。それだけ

## 絶対の約束

1. **キーを注入しない。** `SendInput` も `--accept-injected` も使わない。実キーボードで
   打って確かめること自体が受け入れの目的である（ADR 0069 決定 6）
2. **オーナーが言っていないことを記録に書かない。** 「たぶん通った」で「通過」と書かない。
   報告があいまいなら、通過条件のどれが満たされたのか聞き直す
3. **`-SelfTest` を本番で使わない。** あれは自分でハーネスを試すためのもの。記録に
   「人は打っていない」と残る
4. **終わったら必ず `-Teardown`。** 実運用の設定が退避されたまま終わる状態を残さない。
   中断されたときも、その場で片付けてから返事をする

## 手順

### 1. 始める前に

チェックリストのパスを確かめる（既定は開発中バージョンの `docs/<version>/03_acceptance-checklist.md`）。
そのうえで:

```powershell
.\tests\acceptance\run-acceptance.ps1 <checklist>            # 一覧
.\tests\acceptance\run-acceptance.ps1 <checklist> -Resume    # 未記録＋測れない／不合格だけ
.\tests\acceptance\run-acceptance.ps1 <checklist> -Only C-1,M-4
```

一覧を見せ、**これから何件やるか**と、**準備で機械に何をするか**を先に断る。

- `-Prepare M` / `-Prepare S` は**実運用の設定ファイルを退避して受け入れ用に差し替え**、
  `target\release\winremap.exe` を**起動し直す**（既に起動していれば終了させてから）
- 途中で作業を中断されると設定は退避されたままになる。**まとまった時間が取れるときに
  回すのがよい**ことを言う

チェックリスト §1 の自動側（`cargo test`・UI テスト・`probe-ime-cursor.ps1`）が
緑になっているかも確かめる。**落ちているなら手動へ進まない。** まだなら、先に回すか
どうかを聞く（全部で 30 分弱、うち 26 分が VM。`probe-ime-cursor.ps1` の間は機械に
触れない）。

### 2. 区切りごとに準備する

項目の頭文字（`C` / `M` / `S` / `P`）が区切りである。区切りが変わったら:

```powershell
.\tests\acceptance\run-acceptance.ps1 <checklist> -Prepare M
```

出力の `[人]` の行は**そのままオーナーに伝える**（メモ帳を開く、暗い背景のアプリを
開く、など）。準備ができたと言われるまで次へ進まない。

`P`（MSIX）は破壊的なので自動化しない。チェックリスト §4.1 を読み、何をするかを
説明してオーナーの手に委ねる。

### 3. 1 項目ずつ読み上げる

```powershell
.\tests\acceptance\run-acceptance.ps1 <checklist> -Show M-2
```

出てきた**手順**と**通過条件**を、会話欄に読みやすく整えて出す。過去の記録があれば
それも見せる（前回どう答えたかは、今回の判断の材料になる）。

**1 件ずつ。** まとめて 5 件出して 5 件分の報告を待つ、はしない — どの項目の話か
分からなくなる。

聞き方は「どうでしたか」でよい。**4 択を読み上げる必要はない** — 見えたことを言って
もらい、分類はあなたがやる。

### 4. 報告を分類する

| 結果 | 意味 | 記録に必ず書くこと |
|---|---|---|
| **通過** | 通過条件を満たした | 何をどう確かめたか |
| **不合格** | 満たさなかった | 何が起きたか |
| **未実施** | **今回はやらないと判断した**（「前回から変更が無いので省略」など） | 省略した判断の理由 |
| **測れない** | **前提が揃っていない**（認定待ち・実機が無い） | **何が揃えば測れるか** |

「未実施」と「測れない」を混ぜない。**後者だけが `-Resume` で戻ってくる**ことが、
この区別の実利である。

記録の文は**オーナーの言葉を残す**。特に**どのキーを打ったか**（「US 101 の `;`
（`VK_OEM_1`）」）、**どのアプリで見たか**、**どのターミナルか**は、次の版で根拠に
なる。あなたが要約して情報を落とさない。

分類と記録案は**書き戻す前に見せて確認を取る**。「不合格として、こう書きます」まで
出して、直しがあれば直す。

### 5. 区切りが終わったら書き戻す

回答ファイルを一時ディレクトリに作る（1 行 1 項目、`<id>|<結果>|<記録>`）:

```
C-1|通過|Windows Terminal から --debug。別窓が開き、起動行から全部出た。プロンプトと重ならない
M-5|測れない|カーソルテーマを既定から変えていない。変えている機械が要る
```

```powershell
.\tests\acceptance\run-acceptance.ps1 <checklist> -Record <回答ファイル>
```

**区切りごとに書き戻す。** 最後にまとめて書こうとすると、途中で中断されたときに
その回の報告が全部消える。追記なので何回に分かれてもよい。

### 6. 片付ける

```powershell
.\tests\acceptance\run-acceptance.ps1 -Teardown
```

実運用の設定を戻す。**中断されたときも必ずこれを通す。** そのあと、実運用の WinRemap
を起動し直すかどうかをオーナーに聞く。

最後に、その回の全体的な判断（省略した項目とその理由、次の版へ持ち越すこと）を
チェックリスト §7 に散文で追記する。ここは表に収まらないことを書く欄である。

## 道具の一覧

| 呼び方 | すること |
|---|---|
| `<checklist>` | 一覧（`-Only` / `-Resume` で絞る） |
| `<checklist> -Show C-1,M-2` | 手順・通過条件・過去の記録 |
| `<checklist> -Prepare M` | 設定の退避と配置、WinRemap の起動、`[人]` の手順 |
| `<checklist> -Record <file>` | 記録欄へ追記（環境は自動で刻まれる） |
| `-Teardown` | 実運用の設定を戻す（チェックリストは要らない） |
| `-Environment` | 記録に刻まれる環境の 1 行 |

`-ConfigPath` と `-Exe` で対象を変えられる。ハーネス自身を試すときはこれを一時
ディレクトリへ向け、**実運用の設定に触れずに**確かめること。
