# needs: tray
Use the terminator MCP tools to test a Windows desktop app. Do exactly these steps and do not improvise extra ones.

Output rule: perform all the steps first, then print a line containing ONLY the word PASS or the word FAIL, and only after that line write your short report. Never end without that verdict line, and never stop to ask a question — if something is ambiguous, choose the closest match and say so in the report.

Do not take screenshots and do not read anything from an image. Every check below is answerable from the UI Automation tree. If an element is missing, that is the result — report it as missing rather than looking at the picture to see whether it is "really" there.

1. Launch C:\Test\winremap.exe with the arguments: --config C:\Test\minimal.toml --lang en
2. Wait 5 seconds, then right-click the notification-area icon whose name contains "WinRemap". The icon sits directly on the taskbar — it has been promoted out of the overflow, so do NOT open the overflow flyout (that flyout does not open reliably under automation).
3. Click the menu item whose name is exactly: Show log
   The tray menu is a Win32 popup, and its items are NOT reliably exposed to UI Automation — sometimes they are in the tree, sometimes the popup is an unnamed container with no children at all. That is a property of Windows menus and is not what this test is about. If you cannot find the item in the tree, do NOT report the menu as broken and do NOT take a screenshot. Drive it the way Windows itself allows: with the menu open, press the S key TWICE, then press Enter. ("Settings" and "Show log" both start with S, so the first press highlights "Settings" and the second "Show log" — Windows invokes on a first-letter match only when the match is unique.)
4. Wait 3 seconds, then list the UI elements (role and name) of the window whose name contains "log".
5. Report the log lines. Each line is its own text element; quote them verbatim.
6. Report whether a check box named "Follow newest" and buttons named "Clear" and "Copy all" are present, and what the check box's toggle state is.
7. Click role:Button|name:Clear, wait 2 seconds, and list the window's text elements again.

The window is expected to open on a session line naming the version, such as "2026-07-25 12:00:00  WinRemap v0.4.0 started". Which config file was loaded is NOT written to this window today — do not treat its absence as a failure.

Print PASS if a session line naming WinRemap and its version was readable as a text element, the check box and both buttons were present, and clicking "Clear" removed the log lines. Otherwise print FAIL.
