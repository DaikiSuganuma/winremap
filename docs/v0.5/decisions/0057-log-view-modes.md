# ADR 0057: ログウィンドウを「判定」と「実況」の 2 モードにする

- 作成日: 2026-07-28
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: 採用
- 関連: [ADR 0016（デバッグキーログ）](../../v0.1/decisions/0016-debug-key-logging.md)、[ADR 0041（ローカル時刻）](../../v0.2/decisions/0041-local-time-for-session-banners.md)、[ADR 0032（ログウィンドウの隠蔽）](../../v0.2/decisions/0032-log-window-hide-instead-of-close.md)、不変条件 2・6

> 番号について: **0056 は Phase C（ログへの文字コード表示）の判断に予約済み**（[v0.5 開発計画 §8-4](../01_development-plan.md)）。本 ADR は表示の構造だけを扱い、何を表示してよいかの境界には触れないため、先に 0057 を取った。

## 背景

オーナーから、次のログが「読めない」という指摘があった（2026-07-28）。

```
[debug] a → 素通し
[debug] C-n → Down に置換
[debug]   注入（修飾補正）: LCtrl ↑
[debug]   注入（置換）: Down ↓
[debug]   注入（置換）: Down ↑
[debug]   注入（修飾補正）: LCtrl ↓
```

この 6 行は正しい。読めないのは**構造が見えない**ためで、原因は 4 つある。

1. **6 行が 2 つの時刻にまたがっている**。3・4 行目は `n` を押した瞬間、5・6 行目は `n` を**離した**瞬間の送出である（`sender::send_exact_down` と `send_exact_up`）。ログに時刻が無いので、一続きの出来事に見える
2. **判断と実況が同じ `[debug]` 接頭辞**で、区別は先頭 2 個の空白だけ
3. **物理イベントが虫食い**。`Ctrl` の押下、`a` の解放、`n` の解放は出ない。「入力の実況」として読むと欠けており、「判断の記録」として読むと注入 4 行が過剰
4. `[debug]` が全行に付いていて、**何の情報も持っていない**

つまり 1 つのログが 2 つの目的を中途半端に兼ねていた。「WinRemap は何をしたか」と「実際に何が流れたか」である。

## 決定

**ログウィンドウに 2 つの見え方を用意し、ヘッダーのチェックボックスで切り替える。**

| | 既定（チェック無し） | 詳細（チェック有り） |
|---|---|---|
| ラベル | — | 全イベント / Every event |
| 内容 | キー 1 つにつき 1 行の**判定** | **流れた入力の全部**（物理イベント・送出イベントを含む） |
| 答える問い | 「そのキーで WinRemap は何をした？」 | 「実際には何が流れた？」 |

あわせて表示自体を作り直す。

- **各行を 3 列にする**: 時刻（`HH:MM:SS.mmm`）・種別タグ・本文。時刻が、上記 1 の「2 つの時刻」を見分ける唯一の手がかりになる
  - **ミリ秒まで出す**。押下と解放は 1 秒以内に収まることが多く、秒までだと同じ数字が並んで、この列を設けた意味が消える
  - **直前の行と同じ時刻は空欄にする**。1 回の押下に対する数行は同じ瞬間なので、時刻が変わった行だけが目に入る。同じ数字を 6 行繰り返すと、まさにその区切りが見えなくなる
- **`[debug]` を種別タグに置き換える**: `[入力]`（物理イベント）・`[判定]`（WinRemap の決定）・`[注入]`（WinRemap が送出したもの）・`[操作]`（利用者の操作）。タグは列として描かれ、コンソール出力では本文の前に付く。ウィンドウとコンソールの内容は一致する
- **色は 3 段の濃淡のみ**（`theme.rs` の方針どおり色相を増やさない）: 判定＝本文色、実況＝弱い色、操作とノート＝強い色。詳細モードで判定が実況に埋もれないことが要件
- **行の高さを固定して `ScrollArea::show_rows` で描く**。20,000 行を毎フレーム全部レイアウトしない。長い行は折り返さず横スクロールする（折り返すと列が崩れる）
  - 副作用: **画面外の行は UI Automation のツリーにも出ない**（描かれていない要素はアクセシビリティツリーに存在しない）。ログの中身を読む自動テストは、**見えている範囲だけが読める**前提で書くこと
  - 1 行 1 エントリなので、**改行を含むメッセージは push の時点で分割する**（前面アプリの報告は 3 行ある）。分割しないと行が自分の高さを超え、以降の行がすべてずれる
- **ウィンドウの初期サイズを広げる**（760×480 → 900×720）。詳細モードは同じ操作に対して 3 倍の行を出すため

### 記録は常に行い、表示側で絞る

物理・注入の行は**チェックの状態にかかわらずバッファに入れ**、表示時に絞る。チェックを入れた瞬間に**直前に起きたことの詳細が見える**ようにするためで、「おかしい」と思ってからチェックを入れるのでは遅い、というのがこの機能の使いどころだからである。

その代償としてバッファの行数上限を 5,000 → 20,000 に上げた（リマップ 1 回が 5〜6 行になるため）。20,000 行でも約 1.6 MB で、ディスクには一切書かない（不変条件 6）。

### キーリピートは実況に出さない

物理イベントのうち**オートリピートは記録しない**。押しっぱなしのキーは毎秒数十回発火し、他のすべてを埋めるためで、これは ADR 0016 が既に置いた雑音規則そのものである。リピート中であることは既存の `キーリピート（抑止）` 行が伝える（この行も本 ADR で「実況」側に移した。判定ではあるが、簡易モードに出す価値より雑音の害が大きい）。

したがって詳細モードは「**リピートを除く**完全な実況」である。この限界は上のチェックボックスの説明文には書かず、本 ADR とヘルプに置く。

## 却下した代替案

**チェックが入っている間だけ物理イベントを記録する。** バッファは軽くなるが、チェックを入れた時点より前が空になる。前述のとおり、この機能が要るのは「今起きたこと」を見たいときなので、目的を外す。

**行を 1 本の文字列のままにして、空白で桁を揃える。** 実装は最小だが、日本語のタグ（`[判定]`）は等幅フォントでも欧文の 2 倍幅に揃わない（CJK はフォールバックフォントで描かれ、送り幅が一致しない）。英語表示でしか揃わない見た目は採れない。

**折り返して全文を見せる（横スクロールを出さない）。** マクロ実行行のように長い行があるため折り返しは必要に見えるが、折り返すと行の高さが可変になり `show_rows` が使えず、列も崩れる。ログは表であって文章ではないので、横スクロールを選んだ。

**時刻をイベント発生時に取る。** 正確だが、時刻の取得はフックコールバック内では行えない（不変条件 2）。現在はコールバック外の `drain_debug_log` が動いた時刻を使っている。フックはイベントごとに自スレッドへメッセージを投げる（ADR 0016）ので遅れはミリ秒単位であり、**同じ `SendInput` バッチの数行が同じ秒を示す**のは実態としても正しい。押下と解放が別の時刻になるという、ここで必要な区別は保たれる。

**色相で種別を分ける（注入を青、判定を緑など）。** `theme.rs` はライト/ダーク両対応のため色を `Visuals` から導出する方針で、固定色は片方のテーマで必ず破綻する。濃淡 3 段とタグ列で足りている。

## 実測（2026-07-28、ゲスト `winremap-test`）

`a`（規則なし）と `C-n`（規則あり）を送ったときの実出力。`--debug` でファイルに落としたもので、ウィンドウも同じ内容を 3 列に分けて描く。

```
[input]    a ↓
[decided]  a → passed through
[input]    a ↑
[input]    LCtrl ↓
[input]    n ↓
[decided]  C-n → remapped to Down
[injected] LCtrl ↑ (modifier adjust)
[injected] Down ↓ (remap)
[input]    n ↑
[injected] Down ↑ (remap)
[injected] LCtrl ↓ (modifier adjust)
[input]    LCtrl ↑
```

**指摘のあった「読めなさ」の 3 点がここで解消している。** `Ctrl` を押した事実・`a` を離した事実・`n` を離した事実が出るようになり（旧ログには 1 つも無かった）、**`n ↑` の位置**が「後半 2 行は解放時の出来事である」ことを示している。簡易モードでは `[decided]` の 2 行だけが残る。

## 不変条件との関係

- **不変条件 2（コールバック内の処理制限）**: 追加したのはリングバッファへの `push` 1 回だけで、書式化・時刻取得・ロックはすべて `drain_debug_log`（メッセージループ）側にある。1 キーあたりのイベント数はリマップ時 3→4（押下）・2→3（解放）に増えるが、リングは 128 で、キーイベントごとに drain される
- **不変条件 6（キーロガー化の禁止）**: 表示の粒度は**キー名のまま**で、文字は一切出さない。増えたのは「押した・離した」という事実と時刻だけである。既定 OFF・ウィンドウを閉じるとバッファ破棄・ディスク非保存は変わらない。**何を表示してよいかの境界を動かす判断は Phase C の ADR 0056 で行う**
