## 0. この文書の目的

**v1.1 はコードの置き場所と形を整える版で、振る舞いは v1.0.1 と同じでなければならない**（[開発計画](01_development-plan.md) 原則 P1）。利用者から見える新機能は無い（機能を入れない版にするかどうかは M5 のリリース判断までに決める。計画 §8-1）。

この版の受け入れは「新しく入ったものが動くか」ではなく、**「動いていたものが同じように動くか」**を見る。なかでも次の 2 つが要点である。

1. **リマップ本体に手が入る。** フックの判断ロジックをライブラリの純粋関数へ移す（計画 B3・B4、M4）。v1.0 と v1.0.1 で「リマップ本体に差分が無い」ことを理由に省略した **H-1・H-2・H-7 は、この版では省略できない**
2. **ログの行とファイルの書き戻しが 1 バイトも変わらないこと**を、v1.0.1 と並べて確かめる（R-1・R-2）

### ⚠ この版で特に注意すること

- **v1.0.1 の比較用ログを先に採っておくこと**（§1.1）。v1.1 のビルドを入れてからでは、同じ機械で同じ打鍵列を v1.0.1 に打たせる手間が増える
- **H-1・H-2・H-7 は必ず測る。** 落ちたらリリースしない（v1.0 §5 の注意書きどおり）
- **リリースビルドで通す。** 版番号がトレイのメニュー先頭で確かめられる（`WinRemap v1.1.0`）
- **M4（B3）を見送った場合は、H-1・H-2・H-7 の「必ず測る」が外れる。** そのときは記録に「B3 は v1.2 へ送った」と書き、v1.0 の運用（差分の無い項目は理由付きで未実施）に戻る

## 1. 前準備

### 1.1 R-1 のための v1.0.1 の比較用ログ

v1.1 のビルドを試す**前**に、v1.0.1 のビルドで同じ手順を踏んでログを採る。

1. タグ `v1.0.1` のビルドを用意する。`git worktree add ..\winremap-1.0.1 v1.0.1` して `cargo build --release`、または GitHub Releases の `winremap.exe` 1.0.1
2. `tests/acceptance/manual-minimum.toml` を設定として置く（`run-acceptance.ps1 <この文書> -Prepare H` が退避と配置を行う）
3. `Start-Process <1.0.1 の exe> -ArgumentList '--debug' -RedirectStandardOutput baseline-1.0.1.txt`
4. メモ帳を前面にし、`manual-minimum.toml` にある規則を一巡する打鍵列を打つ: `abc` と打って `C-h`（1 文字消える）、`C-a`（行頭へ）、`S-F10` で記憶を始めて `C-a` を 2 回、`S-F10` で止め、`F10` で再生、`C-Space` で IME をオン・オフ。打鍵列は記録に書き残す
5. トレイから終了し、`baseline-1.0.1.txt` を手元に置く

v1.1 のビルドで同じ 2〜5 を行い、`baseline-1.1.0.txt` を採る。比較は §2 の R-1 の手順。
