# ADR 0059: 初回起動時に既定の設定ファイルを作る

- 作成日: 2026-07-29
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: 採用
- 関連: [ADR 0027](../../v0.1/decisions/0027-windows-installer-inno-setup.md)（Inno Setup によるインストーラー化）、[ADR 0050](../../v0.4/decisions/0050-config-file-switching.md)（設定ファイルの切り替え）、[v0.1 設定仕様](../../v0.1/02_config-spec.md) §4（設定エラーでは起動しない）

## 背景

設定ファイルが無いとき、WinRemap は起動を拒否していた。

```rust
// src/main.rs（変更前）
if !path.exists() {
    bail!("{}", i18n::no_config_file(&path));
}
```

これが問題として表に出てこなかったのは、**インストーラーが代わりにファイルを置いていた**ためである（`installer/winremap.iss`）。

```
Source: "..\examples\minimal.toml"; DestDir: "{userappdata}\winremap"; DestName: "config.toml"; Flags: onlyifdoesntexist uninsneveruninstall
```

つまり「初回起動が成立する」という前提が、アプリではなくインストーラー側に置かれていた。この前提は 3 つの配布形態のうち 1 つでしか成り立たない。

| 配布形態 | 初回起動 |
|---|---|
| インストーラー（`winremap-setup.exe`） | 成立する（Inno が配置） |
| ポータブル（`winremap.exe` 単体） | **失敗する**。利用者が自分で作る必要がある |
| MSIX パッケージ（Microsoft Store） | **失敗する**。インストール時スクリプトという仕組みが存在しない |

MSIX には Inno の `[Files]` に相当する「ユーザーのプロファイルへファイルを配置する」手段がない。パッケージ内の `VFS` フォルダは読み取り専用のマージであり、しかも公式ドキュメントが *"the OS doesn't support a virtual file system (VFS) folder for the user's `AppData` folder"* と明記している（[Understanding how packaged desktop apps run on Windows](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)）。Store 配信を始めれば、**インストール直後の初回起動が必ずエラーで終わる**。

ポータブル版で既に起きていた問題が、MSIX 対応で回避不能になった、というのが正確な経緯である。

## 決定

**既定パスに限り、設定ファイルが無ければ作ってから起動する。**

1. `%APPDATA%\winremap\config.toml` が無い場合、`examples/minimal.toml` の内容で作成する。親フォルダも作る
2. `--config` で明示されたパスが無い場合は、従来どおりエラーで停止する
3. 既存ファイルは決して上書きしない（`File::create_new`）
4. 作成したことをセッションログの 1 行で告げる（`既定の設定ファイルを作成しました: <path>`）

既定の内容はインストーラーが配置しているものと同一で、`include_str!("../../examples/minimal.toml")` で埋め込む。コピーを 2 つ持たないため、そして「インストール版とポータブル版で最初の設定が違う」という状態を構造的に不可能にするためである。

### 2 を分けた理由

`--config` に渡されたパスは、利用者が**そのファイルを使いたいと名指しした**ものである。存在しないときに黙って作ると、打ち間違いが「キーマップ 0 件で起動し、何もリマップしない WinRemap」として現れる。エラーで止めれば打ち間違いだと分かる。既定パスは名指しではなく既定値なので、同じ扱いにする理由がない。

### 3 に `create_new` を使った理由

`exists()` で確認してから書くと、その間に別プロセスが書いた場合に上書きしうる。WinRemap は単一インスタンスだが、mutex を取るより前に 2 つのプロセスがここへ到達する可能性は残る。利用者の設定を消す事故は、実装を 1 行変えるだけで構造的に防げる。

## 却下した代替案

- **空ファイルを作る**: パースは通るが、キーマップ 0 件のまま常駐する。利用者から見ると「起動したのに何も起きない」で、壊れているのか設定が空なのか区別できない。`minimal.toml` は Notepad で `C-h` を押せば動作確認できる内容になっており（そのために書かれた）、初回の 1 ファイルとしてこれ以上のものはない

- **既定のキーマップをメモリ上だけで持ち、ファイルを作らない**: 設定ウィンドウを開いた瞬間に保存先が無い問題に変わる。ADR 0050 の設定ファイル切り替えもファイルの存在を前提にしている。問題を後ろにずらすだけである

- **MSIX パッケージ側で解決する**: 上記のとおり `AppData` への VFS が存在しない。仮に別の手段（初回起動時に走るスクリプトを仕込む等）を見つけても、ポータブル版は救われないままである

- **起動は続けてトレイに警告を出す**: 設定仕様 §4 の「設定エラーでは起動しない」方針と衝突する。ただしこの方針が守っているのは「利用者が意図した設定と違う状態で動かさない」ことであり、**設定ファイルがまだ無い状態はエラーではなく初回である**。両者を区別するのが本 ADR の趣旨で、方針そのものは変えていない

- **インストーラーの配置をやめてアプリ側に一本化する**: 正しい方向だが、`onlyifdoesntexist` が付いており実害がない。インストーラーを触ると受け入れテストの範囲が広がるため、本件では変更しない（将来 MSIX が主配布になったら再検討）

## 不変条件への影響

- **不変条件 2（フックコールバック内の処理制限）**: 変更なし。ファイル生成は `run()` の起動シーケンス、フック設置より前の 1 回のみ
- **不変条件 3（unsafe の隔離）**: 変更なし。`std::fs` のみで unsafe を含まない
- **不変条件 6（キーロガー化の禁止）**: 変更なし。書き出すのは同梱テンプレートの固定文字列であり、入力に由来するものは何も含まない

副次的な整理として、`parse_args` から副作用（存在確認）を外した。引数の解析がファイルシステムを触っていると、テストが実環境の `%APPDATA%` に依存する。作成は `ensure_config` に分離し、起動シーケンスから呼ぶ。

## 確認方法

`src/config/tests.rs` に 3 件追加した。

| テスト | 何を保証するか |
|---|---|
| `the_default_config_is_valid` | 埋め込んだ既定設定がパースできる（作ってから起動に失敗する、が起きない） |
| `create_default_writes_a_loadable_config` | 親フォルダごと作られ、書いたものがそのまま読み込める |
| `create_default_refuses_to_overwrite` | 既存ファイルは `AlreadyExists` で拒否され、中身が変わらない |

手動確認は、`%APPDATA%\winremap\` を退避してからポータブル `winremap.exe` を起動し、ファイルが作られてリマップが有効になること、`--config nonexistent.toml` では従来どおり停止することを見る。
