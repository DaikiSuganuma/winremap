## 0. このバージョンの性格

v0.6.0 は**機能ではなく配布経路のバージョン**である。動機は 1 つしかない。

> **「Windows によって PC が保護されました」**

利用者がダウンロードした `winremap.exe` / `winremap-setup.exe` に SmartScreen の警告が出る。これを消したい、というオーナーの要望（2026-07-29）が起点である。

調査の結果、**この警告を確実に消せる経路は Microsoft Store だけ**だと分かった。Microsoft の公式ドキュメントは、非 Store 配信では署名しても警告は消えない（評判はダウンロード数で蓄積する）と明示し、かつて即座に信頼を得られた EV 証明書についても *"EV certificates no longer bypass SmartScreen"* と否定している。Store 配信では Microsoft がパッケージを再署名するため、**証明書は不要かつ購入不可**である。

したがって本バージョンのスコープは **MSIX パッケージ化と Microsoft Store への提出**となる（オーナー決定 2026-07-29）。

### v0.5 の提案からの変更

[v0.5 開発計画 §1](../v0.5/01_development-plan.md) の見送り表は、**記号キー（OEM キー）対応を「v0.6 以降で単独のバージョンの目玉として扱う」**ことを提案していた。本バージョンではこれを行わない（オーナー決定 2026-07-29）。

理由は、SmartScreen 警告が**今この瞬間も全ての新規利用者に出続けている**のに対し、記号キー対応は既存利用者の機能拡張だからである。前者は導入の入口そのものを塞いでおり、優先度が上である。記号キー対応は **v0.7 の目玉**として送る。**3 回目の先送りは認めない**（v0.5 が回帰確認で経験した構造）。

#### 再現確認（2026-07-29、開発機・リリースビルド）

Phase B の撮影で、ログウィンドウを開いた状態の打鍵がすべて「素通し」になり、この持ち越しが**表示だけでなく変換結果を狂わせる不具合**なのではないかと疑った。ログウィンドウのテキストを UI Automation で読む形で測ったところ、**そうではなかった**。

```
13:33:27.861  launching notepad
13:33:28.039  application = "notepad.exe" — matching keymaps: notepad, everywhere
```

ログウィンドウを開いたまま Notepad を起動しても、前面アプリの変化は **0.2 秒で報告**され、適用キーマップも正しく解決されている。

素通しの原因は撮影スクリプト側だった。Notepad を起動しただけでフォーカスが移ると仮定していたが、**フォアグラウンド権を持たないプロセスから起動したウィンドウを Windows は前面にしない**。打鍵は前面のままだったウィンドウ（`winremap.exe`）に入り、そこに適用される `everywhere` キーマップに `C-h` が無いため、**正しく素通しされていた**。

v0.5 の観測は VM の UI テスト環境で得られたものであり、本測定は開発機である。環境が違うため**観測を取り消しはしない**が、少なくとも開発機のリリースビルドでは再現しないことを記録する。

方針はブリーフどおり **1 機能 1 ADR**、各フェーズ着手前にオーナー承認を得る。

#### この Phase で分かったこと（以後に効く）

**1 枚の画像を撮るのに 5 回かかった。** 原因はすべて撮影スクリプト側で、アプリは一貫して正しく動いていた。記録に値するのは、いずれも「自動化が黙って間違った結果を出す」形だった点である。

| 失敗 | 原因 |
|---|---|
| ログが空 | メニュー位置を上から探る実装が、途中で **Enabled を選んでリマップを OFF** にしていた |
| 全キーが「素通し」（2 回） | `SetForegroundWindow` は**フォアグラウンド権が無いと何もせず成功を返す**。Notepad は裏のままで、打鍵は前面の別ウィンドウに入り、そこのキーマップで正しく素通しされていた |
| 前面待ちが機能せず | プロセスが見つからない場合に確認ごとスキップし、見つかっても 30 秒で諦めて続行していた |
| 他ウィンドウの写り込み | 画面から矩形を切り出すため、手前に何かあれば入る。**Z オーダー固定**（フォアグラウンド権不要）で解決 |
| ログにノイズ | 実行中にスタートメニューから Notepad を開くと `searchhost.exe` 等の行が入る。**起動前に開いておく**方式に変更 |

**合成入力はリマップされない**（不変条件 1）ため、ログの内容は人が打つしかない。この 1 枚だけは自動化できない。

**アプリ側の疑いは晴れた。** 一時は「ログウィンドウを開いていると変換が効かない」不具合を疑ったが、実測で否定した（§1 の再現確認）。

## 8. フェーズ順序と依存関係

```
Phase A（MSIX 基盤）【完了】
   │
   ├──▶ Phase B（掲載情報・スクリーンショット） ──┐
   ├──▶ Phase C（既存記述の Store 対応） ─────────┤
   └──▶ Phase D（リリース運用手順） ──────────────┤
                                                  │
                                Phase E（受け入れ）◀┘
                                        │
                                        ▼
                     Phase F（リリース → Pages 発行 → Store 提出）
```

- **B・C・D は互いに独立**。並行して進められる
- **Phase C は Phase F より前に完了していること**。リリース後に文書を直すと、公開された版の記述が嘘のまま残る（v0.4 の教訓）
