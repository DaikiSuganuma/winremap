# v1.0.0 の方針（オーナー決定）

- 作成日: 2026-08-14
- 作成: Claude Code（AI モデル: claude-fable-5）／決定: オーナー

## v1.0.0 の意味合い

WinRemap の v1.0.0 は、**オーナーが現在の機能セットにある程度満足したことの表明**である。何かを凍結する宣言ではなく、設定ファイルの書式や CLI フラグについて新たな互換性の約束を追加するものでもない（互換性には従来どおり配慮する。それ以上でも以下でもない）。

## 移行の基準

**v0.9.0 を約 1 か月運用し、hotfix 級の不具合が出なければ v1.0.0 へ移行する。**

`docs/v1.0/` の準備（開発計画の作成）はまだ行わない。保存すべき文書ができた時点でフォルダを作る（`docs/README.md` の構成ルールどおり）。

## 次のリリースで対応したいこと（2026-08-14 時点の候補）

### 1. スタートアップ登録方法をヘルプページに記載する

現状、ヘルプサイト（install / faq）にスタートアップの記載が無い。配布形態ごとに機構が違う:

| 配布形態 | 機構 | 現状の案内 |
|---|---|---|
| Store 版 | MSIX の `StartupTask`（既定 OFF）。「設定 → アプリ → スタートアップ」で有効化 | 無し（分かりにくい） |
| GitHub（Inno）版 | インストーラーがスタートアップフォルダーにショートカットを作成 | 無し |
| scoop 版 | 何も無い | 無し |

あわせて、**設定ウィンドウからスタートアップ登録を切り替えられるようにする**ことも検討する。ただし:

- Store 版は `StartupTask.RequestEnableAsync` で有効化できるが、利用者が一度「設定」アプリで OFF にすると `DisabledByUser` となり、アプリからは再有効化できない（Windows の仕様）。その場合は設定アプリへ誘導するしかないため、**トグルを実装してもヘルプ記載は不要にならない**。参照: <https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.startuptask>
- 配布形態ごとの分岐（`src/package.rs`、ADR 0061）、ショートカット方式と Run キー方式の選択、unsafe 隔離リストへの影響など設計判断が多いので、実装するなら ADR から始める。

ヘルプ記載だけならドキュメントのみの変更なので、リリースを待たず `develop` → `main` で出せる（`docs/04_git-branching.md` §2.5.1）。

### 2. ヘルプページに自前ビルド方法を記載する

eframe のフォーク指定（`[patch.crates-io]`）は Cargo.toml にコミット済みなので、**`cargo build` するだけでフォークも自動取得され、手順自体は今でも書ける**。egui 本家への PR（[emilk/egui#8410](https://github.com/emilk/egui/pull/8410)）の状況で変わるのは「なぜフォークを当てているか」の注記だけ。

- 当面は「現在の手順＋フォークの注記」で記載する
- PR が upstream に入り、公開版の eframe に載った時点で、注記と Cargo.toml のパッチを一緒に削除する
- egui 側のリリース時期は読めないため、**パッチ除去を v1.0.0 の条件にはしない**
