# ADR 0075: 半分だけ着いた着色は、そう言わなければならない

- 作成日: 2026-08-13
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: **承認（2026-08-13）**。[v0.9 受け入れ](../03_acceptance-checklist.md) M-2 の不合格を受けた修正
- 関連: [ADR 0073](0073-restore-from-a-snapshot-taken-at-startup.md)（**本 ADR はその決定 3・4 の報告経路を直す**）、[ADR 0067](../../v0.8/decisions/0067-ime-cursor-color.md)（IME をマウスカーソルの色で示す）、[ADR 0016](../../v0.1/decisions/0016-debug-key-logging.md)（デバッグログの雑音の規律）
- 公式: [`SetSystemCursor`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setsystemcursor)

## 背景

**2026-08-13 の v0.9 受け入れ M-2 が落ちた。** 症状は ADR 0073 の「影響・補足」が予告していた形そのものである。

> 壊れる経路が別にあれば、空は作られないが**着色が入らない**という形で出る

矢印は着色され、**I ビームだけが素のまま**になった。空のカーソルは 1 つも入っていない — **決定 3・4 の守りは効いた**。効かなかったのは、**そのことを人に伝える経路**である。

### 起きたこと

WinRemap は 16:17:13 に起動し、16:37 に起動し直すまで **20 分間、着色を半分だけ着けたまま走り続けた**。その間ログはこう言い続けた。

```
16:23:21.092 [IME]   カーソル: 着色した — 差し替え 1
```

**「差し替え 1」が異常である**ことは、差し替える対象が 2 つ（`OCR_NORMAL` と `OCR_IBEAM`）だと知っている者にしか読めない。**失敗は 0 と報告されている。** 起動し直した後は `差し替え 2・作り直し` になり、症状は消えた。**間欠的である。**

### 欠陥 1 — 落ちた 1 件が、数に現れない

```rust
let cursors: Vec<_> = REPLACED
    .iter()
    .filter_map(|(id, name)| tinted(*id, *name, color).map(|cur| (*id, cur.0 as isize)))
    .collect();
```

`filter_map` が作成に失敗した分を**集合から落とす**。以後の設置ループはそれを見ないので、`failed` に加算する機会そのものが無い。**「2 つとも着けた」と「1 つしか着けなかった」が、ログ上で同じ文になる。**

`failed` は**失敗を数え上げて**作られていた。数え上げは、**数え上げる場所を通らなかった失敗**を取りこぼす。

### 欠陥 2 — 理由が、聞いている者のいない時刻に一度だけ言われる

`report()` は `gui::log::emit()` を呼ぶが、その先はこうである。

```rust
fn store(line: Line) {
    if !OPEN.load(Ordering::Relaxed) {
        return;      // ログウィンドウが開いていなければ捨てる
    }
```

そして**着色カーソルの作成は色ごとに 1 回きり**で、たいていは起動の数秒後に走る。**`--debug` を付けているか、ログウィンドウを最初から開いていない限り、理由はどこにも残らない。** 今回まさにそうなった — オーナーがログを開いたのは 6 分後で、その時にはもう言い終わっていた。しかも作成は繰り返されないので、**二度と言い直さない**。

**ADR 0073 が「次に出たら `--debug` に理由が残る」と書いた約束は、実地で果たされなかった。** この版の値打ちの中心が、ここで空になっていた。

## 決定

### 決定 1 — `failed` は数え上げず、差し引きで出す

```rust
failed: (REPLACED.len() as u8).saturating_sub(replaced),
```

**`REPLACED` が名指しているもののうち、設置されなかったものすべて**が失敗である。作成で落ちたのか、`CopyIcon` で落ちたのか、`SetSystemCursor` で落ちたのかを、**数は知らなくてよい**。知らないからこそ、**経路を取りこぼせない**。

この計算を `outcome()` という純粋関数に切り出し、テストで固定した。**Win32 を呼ばずに「半分だけ着いた着色は失敗 1 と数える」を確かめられる**ようにするためである。

### 決定 2 — 作れなかった理由を覚えておき、着色のたびに言い直す

`Prepared` に `missing: Vec<Trouble>` を持たせ、**IME がオフからオンになるたび**に再び報告する。

**`Reinstalled`（すでに着色済み）では言わない。** そちらは前面が変わるたびに走るので、説明が雑音に変わる（ADR 0016 の規律）。**オフ→オンは人が意図して行う操作**で、多くても毎分数回である。

これにより、**「ログを開いて IME を 1 回入れ直す」ことが、理由を尋ねる手順になる**。今回のように 20 分後に気づいた場合でも、その場で聞き直せる。

### 決定 3 — `tinted()` は理由を返し、報告は呼び出し側で行う

`Option<HCURSOR>` から `Result<HCURSOR, Trouble>` に変えた。**理由を覚えておくには、まず理由が値として戻ってくる必要がある。** 関数の中で報告して `None` を返す形では、呼び出し側は「何かが失敗した」ことすら分からない。

## 却下した案

- **ログウィンドウが開いていない間もバッファに溜める** — `store` が捨てるのは意図的な設計で、「閉じている窓のためにヒープを伸ばさない」という判断がある。**溜める量の上限と、いつ捨てるかという新しい問いが増える**。決定 2 は覚える対象を「いま壊れている理由」だけに絞るので、上限は `REPLACED` の要素数で自明である
- **着色のたびに毎回、理由を言う** — `Reinstalled` は前面が変わるたびに走る。Zed とメモ帳を行き来するだけで同じ 1 行が積み上がり、ADR 0016 が禁じた雑音になる
- **`failed` の数え上げに、落ちた分を足す** — 直る。ただし**次に経路が増えたとき、また足し忘れられる**。差し引きは足し忘れようがない
- **半分だけの着色を、そもそも設置しない**（全部揃わなければ何も着けない） — **利用者にとって明確に悪い**。矢印だけでも色が付いていれば IME の状態は読める。**見えるものを減らして、報告の正しさを買うことになる**

## 影響・補足

- **原因は、依然として特定していない。** 直したのは**報告**であって、I ビームの作成が時折失敗すること自体ではない。**次に出たときに、何が起きたのかが言葉で残る**ようになっただけである
- **その「次」は、今度こそ残る。** 今回失われたのは `SourceEmpty` / `ResultEmpty` / `BuildFailed` のどれかで、**どれであるかが分かれば原因の範囲は大きく狭まる**（元が空だったのか、作った結果が空だったのか、Win32 の呼び出しが断ったのか）
- **`cargo test` が 142 件から 145 件になった。** 増えた 3 件はすべて `outcome()` に対するもので、うち 1 件は今回の不合格そのものを固定している
- **受け入れの M-1〜M-6 はやり直しである**（バイナリが変わったため）。C・H・P は未着手なので影響しない
