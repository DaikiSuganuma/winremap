# ADR 0073: カーソルの復元は起動時に採った複製から行い、空の着色は入れない

- 作成日: 2026-08-09
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: **承認（2026-08-09）**。[v0.9 開発計画 §2](../01_development-plan.md) Phase A の方式
- 関連: [ADR 0067](../../v0.8/decisions/0067-ime-cursor-color.md)（IME をマウスカーソルの色で示す。**決定 5 の「起動時の無条件復元」を作り直す**）、[ADR 0072](../../v0.8/decisions/0072-cursor-keeps-tint-when-state-unknown.md)（状態が不明のときは色を動かさない）、[M-2 の調査ノート](../../v0.8/notes/20260809_m2-empty-ibeam.md)（本 ADR の全根拠）
- 公式: [`LoadImage`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-loadimagew)／[`CopyIcon`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-copyicon)／[`SetSystemCursor`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setsystemcursor)（渡したハンドルを破棄する）／[`SystemParametersInfo`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow)（`SPI_SETCURSORS`）

## 背景

v0.8 の受け入れ **M-2** が 4 回落ちた。症状は「**着色した I ビームがまったく描かれなくなる**」で、矢印は無事、IME を切り替えても戻らず、WinRemap を起動し直すと戻る。2026-08-09 に症状が出ている最中を測って、正体が分かった。

```
id 32513 (I ビーム): colour 32x32, ホットスポット (9,10)
                     マスク AND=1 が 1024/1024（全面透明）
                     アルファ 0 が 1024/1024
```

**素の I ビームはマスクだけのカーソル**（32×64・下の画面を反転して描く）である。入っていたのは**カラーカーソル 32×32 でホットスポットが I ビームのもの** — `tinted()` が作った出力で、その中身が**完全に空**だった。

**原因は特定できていない。** 6 つの筋を実測で否定し、自動再現も 2 通り試して出なかった（調査ノート §4）。だが**確定した欠陥が 2 件**あり、どちらも単独で直す価値がある。

### 欠陥 1 — `restore()` の 1 段目が、この Windows では一度も動いていない

```
LoadImageW(user32, IDC_ARROW, IMAGE_CURSOR, 0, 0, LR_SHARED) -> 0  (GetLastError=1814)
LoadImageW(user32, IDC_IBEAM, ...)                           -> 0  (GetLastError=1814)
LoadImageW(NULL,   IDC_IBEAM, ...)                           -> 0x10005  (成功)
```

`1814` は `ERROR_RESOURCE_NAME_NOT_FOUND`。[`src/cursor.rs`](../../../src/cursor.rs) は「`IDC_*` のアトムは user32 内のこのカーソルのリソース ID でもある」という前提で書かれているが、**Windows 11 26200 では成り立たない**。失敗は `continue` で捨てられる。

**したがって復元は `SPI_SETCURSORS` の 1 段だけで回っている。** ADR 0067 が「既定スキームではレジストリの値が空で、`SPI_SETCURSORS` だけでは戻らないことがある」として 2 段構えにした、その 1 段目が**機能の導入時から一度も動いていなかった**。

この機械のレジストリはまさにその状態である（`IBeam` が空、`Arrow` だけ `aero_arrow.cur`）。**矢印が壊れず I ビームだけ壊れる**という非対称は、これで説明が付く。

### 欠陥 2 — 作った結果も、元にする対象も、誰も検査していない

`tinted()` は結果を検査せず、`apply()` は元カーソルを検査しない。そして `from_color()` は「アルファが無ければ AND マスクを見る」ので、**空のカーソルを元にすると、また空を作る**。**一度入ると自己再生産する** — IME を切り替えても戻らなかった理由である。

## 決定

1. **起動時に、素のカーソルの複製を採って持つ。復元はそこから行う。** 採るのは `cursor::restore()` を呼ぶ前、つまり**この版がまだ何も差し替えていない時点**である
   - 採り方は `LoadImageW(NULL, IDC_*, …)`（**モジュール指定なし**。実測で成功する）＋ `CopyIcon`。プロセスの寿命のあいだ持ち続ける
   - **前の実行が汚したまま死んでいた場合、採れるのは「汚れたカーソル」である。** それを掴まないために、**採る前に `SPI_SETCURSORS` を 1 度打つ**（これは実測で空のカーソルを素に戻せている）。そのうえで**採ったものが空でないことを確かめ**、空なら持たない
2. **複製を持てなかったときは `SPI_SETCURSORS` だけで復元する**（現在と同じ挙動）。**そのことをログに残す**
3. **可視画素が 1 つも無い着色カーソルは、作らない・入れない。** 作ってしまった場合は捨て、ログに残す。**これだけで利用者から見える症状は消える**
4. **元にするカーソルが空なら、着色を作らない。** 欠陥 2 の自己再生産を断つ
5. **失敗を黙って捨てない。** `restore()` / `apply()` の `continue` と `let _ =` をログに出す（v0.8 で `apply()` の戻り値に対して行ったのと同じ形）
6. **`probe-ime-cursor.ps1` に「着色 → 復元 → 着色」を繰り返す項目**を足し、繰り返しの中で空にならないことを見る

**ADR 0067 決定 5（起動時の無条件復元）は維持する。** 変えるのは「何から復元するか」であって、「いつ復元するか」ではない。

## 理由

- **決定 1 が本筋である。** 「user32 から素のカーソルを読み直す」という前提が成り立たない以上、**素のカーソルを知っている唯一の時点は自分の起動時**である。そこで複製を採るのが、外部の前提に依存しない唯一の方法である
- **決定 3 は安いのに効く。** 原因が特定できていなくても、**空を入れないだけで利用者から見える症状は消える**。原因究明の完了をリリースの条件にしないで済む
- **決定 4 は再発の連鎖を断つ。** 空が 1 度入ったあと「IME を切り替えても戻らない」という最も厄介な性質は、ここから来ている
- **決定 5 は今回の教訓そのものである。** 1814 は**機能の導入時からずっと返っていた**のに、誰も気づけなかった。捨てた戻り値は、次に同じことが起きたときも捨てられる

## 却下した代替案

- **user32 内の正しいリソース ID を調べて 1 段目を直す**: リソース ID は文書化されておらず、Windows の版で変わりうる。**同じ罠をもう一度踏む**構造が残る。実測で `1814` が出ている以上、この前提に依存し続けない
- **`%SystemRoot%\Cursors\*.cur` から読む**: 既定スキームの機械はレジストリにファイルを持たない（この機械の `IBeam` が空である）。**何を読むべきかが決まらない**
- **前回の状態を痕跡ファイルに記録する**: [ADR 0067](../../v0.8/decisions/0067-ime-cursor-color.md) 決定 4・5 が「痕跡ファイルは置かない」と決めている。**色が残っていてトレイに居なければ異常終了、という読み方**はその決定の上に成り立っており、覆すと文書（README・ヘルプサイト）も含めて崩れる
- **検査（決定 3・4）だけ足して復元は放置する**: 症状は消えるが、**安全網が外れたままになる**。強制終了で色が残る設計（ADR 0067 決定 4）は「次の起動で戻る」ことと対で成立しており、そこが効いていないのは設計の欠落である
- **カーソルの色替え機能そのものを取り下げる**: v0.8 の目玉であり、オーナーが日常的に使っている。原因未特定を理由に機能を落とすのは、症状が「起動し直せば戻る」程度であることに対して重い

## 影響・補足

- **プロセスの寿命のあいだ、カーソルのハンドルを 2 つ余分に持つ。** 現在も着色版を 2 つ持っており（`TINTED`）、性質は同じである
- **`SetSystemCursor` は渡したハンドルを破棄する**ので、複製を持つ側は毎回 `CopyIcon` してから渡す。ここは現行のままでよい
- **原因は依然として未特定である。** 本 ADR は「症状が利用者に届かないようにする」ことと「安全網を実際に効かせる」ことの 2 つを行うもので、**壊れる契機そのものを突き止めたわけではない**。壊れる経路が別にあれば、空は作られないが**着色が入らない**という形で出るはずで、それは決定 3・5 のログに残る
- **手掛かりが 1 つ残っている。** 壊れたカーソルのホットスポットは `(9,10)`、正常に作られたものは `(8,9)` だった。`tinted()` は元のホットスポットを引き継ぐので、**壊れたほうは別の元から作られている**。次に捕まえたときはここを見ること
- **テストは受け入れの検査で行う**（決定 6）。`cursor.rs` はフック層ではないが、セッション全体の状態を触る層で単体テストの対象外である
