# ADR 0082: 小さいサイズは専用のマスターから焼き、トレイが要求する全サイズを `.ico` に持つ

- 作成日: 2026-08-17
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: **承認（オーナー指示 2026-08-17「白い点が小さく、何のものかわからないので、白い部分を拡大してはっきり見せたい」→ 図柄は現行のまま小サイズを手でリデザインする方針を選択、「推奨通りにしたい」）**
- 関連: [ADR 0010](../../v0.1/decisions/0010-icon-embedding.md)（アイコンは exe に埋め込む。正本は `assets/svg/`）、[ADR 0080](0080-tray-icon-asks-for-the-small-metric.md)（通知領域のサイズを指定して読む）、[ADR 0081](0081-icon-must-not-depend-on-its-background.md)（背景に依存しない絵にする）、[ADR 0060](../../v0.6/decisions/0060-msix-package.md)（MSIX の資産を SVG から焼く）
- 作り方の手引き: [docs/06_icon-assets.md](../../06_icon-assets.md)

## 背景

[ADR 0081](0081-icon-must-not-depend-on-its-background.md) で「抜き」を「白い塗り」に変え、設定アプリの一覧の青ベタは解消した。オーナーの実機確認（I-1・I-2）も通った。

そのうえで**残った不満**がある — **白い部分が小さすぎて、何の絵なのか読めない**。

原因は 2 つある。

### 1. 1 枚のマスターが 16 px から 256 px までを兼ねている

現行の `kbd-enabled.svg` はキーを 4 つ並べ、1 つの幅が 2 単位（16 単位系）である。16 px では 2 px、隙間は 1 px になる。256 px では素直な絵だが、**16〜24 px では絵として成立しない**。

### 2. `.ico` が持つ面が足りていない

通知領域が要求するのは `SM_CXSMICON`、すなわち 16 px にスケールを掛けた値である。

| 表示スケール | トレイが要求 | v1.0.0 の `.ico` に有ったか |
|---|---|---|
| 100% | 16 | 有り |
| **125%** | **20** | **無し** |
| 150% | 24 | 有り |
| **175%** | **28** | **無し** |
| 200% | 32 | 有り |

**125% と 175% の利用者には、要求されたサイズの面が無く、Windows が拡縮していた。** [ADR 0080](0080-tray-icon-asks-for-the-small-metric.md) が直したのは「どのサイズを要求するか」で、「そのサイズが `.ico` に有るか」は見ていなかった。開発機が 150% だったので気づけなかった。

## 決定

### 決定 1 — 小サイズ専用のマスターを持ち、トレイが使い切る 32 px までを担当させる

```
assets/svg/kbd-enabled-small.svg     （有効）
assets/svg/kbd-disabled-small.svg    （無効）
```

| サイズ | マスター | 用途 |
|---|---|---|
| 16 / 20 / 24 / 28 / 32 | **小** | **トレイ（100%〜200% の全域）**、MSIX の小 targetsize |
| 40 / 48 / 256 | 通常 | エクスプローラー、Alt+Tab、ウィンドウの大アイコン、タイル、Store |

**境目を 32 に置いたのは、そこがトレイの使い切るサイズだからである。** 中途半端な位置で切ると、**利用者が拡大率の違うモニター間でウィンドウを動かしたときにトレイの絵の形が変わる**。

サイズごとに絵を描き分けるのは一般的な手法（optical sizing）で、macOS も Windows のシステムアイコンもそうしている。

### 決定 2 — 小マスターは任意とし、無ければ通常マスターで代用する

`app_icons` と `msix_assets` は、小マスターが無ければ通常マスターで全サイズを焼き、**代用したことを出力に書く**。

絵を描くのはオーナーの仕事であり、**絵が用意される前にビルドが壊れる作りにしない**。黙って代用すると気づけないので、必ず言う。

### 決定 3 — `.ico` にトレイの全サイズ（16/20/24/28/32）と 40 を足す

**`.ico` に無いサイズは Windows が拡縮する。** それが [ADR 0080](0080-tray-icon-asks-for-the-small-metric.md) の直した不具合の残りである。

56 と 64（175%・200% の大アイコン）は入れない。大アイコンの面は 24 px のトレイ枠ほど拡縮に敏感でなく、フレームは非圧縮なので 64 px 1 面で 17 KB 増える。`.ico` は 19 KB から 31 KB になった。

### 決定 4 — 作り方を版に依存しない文書として持つ

[docs/06_icon-assets.md](../../06_icon-assets.md) に、正本と生成物の別・サイズの割り当て・Illustrator の設定と描画のルール・書き出し設定・確認手順・やりがちな失敗をまとめる。

**ADR は判断の記録であって手順書ではない。** アイコンを描き替えるのはこの先も起きることで、そのたびに ADR を読み返させるのは筋が違う。

## 理由

- **1 枚で兼ねるのをやめれば、小さいところで無理をしなくてよくなる。** 256 px の絵の情報量を 16 px に押し込もうとしたことが、そもそもの原因である
- **要求されるサイズを全部持てば、拡縮が起きない。** これは絵の巧拙と無関係に効く
- **代用を許すことで、道具の変更と絵の作成を切り離せる。** 今回、絵ができる前に生成側だけ先に入れられた

## 却下した代替案

- **アイコンを単色（白か黒）にする** — Windows の通知領域に単色の要求は無い（macOS のメニューバーの慣習である）。同じ絵が exe のアイコンと Store のタイルを兼ねているので、白単色はエクスプローラーの白地で、黒単色はダークテーマで消える。Windows には macOS の template image に当たる仕組みが無い。**加えて色が状態を持っている**（青＝有効、灰色＝無効）ので、単色化するとこの区別が潰れる。実測でも `#0078D4` は明るいタスクバーに 4.1:1、暗いタスクバーに 3.6:1 で、図形の基準 3:1 を満たしている
- **サイズごとに 1 枚ずつマスターを描く（16 用・20 用・24 用…）** — 5 枚の維持は現実的でない。描き替えるたびに 5 枚が食い違う
- **小マスターを必須にする** — 絵が用意されるまでビルドが通らなくなる。決定 2 のとおり
- **56 と 64 も入れる** — 決定 3 のとおり、費用対効果が薄い。必要になれば `SIZES` に 1 行足すだけである
- **`.ico` を全面 PNG 圧縮フレームにしてサイズを抑える** — 古い経路の互換性を確かめる手間に見合わない。31 KB は exe にとって誤差である

## 影響・補足

- **小マスターはまだ存在しない。** オーナーが Illustrator で描く。それまでは通常マスターで代用され、生成時にその旨が出る
- **⚠ 絵を描き替えたら受け入れの I 区切りを測り直すこと。** そして**設定アプリの一覧は行の作成時に撮った PNG を表示する**ので、既存の行を見ても変わらない（[ADR 0081](0081-icon-must-not-depend-on-its-background.md) 実測 2）。手順は [v1.0.1 §1.1](../03_acceptance-checklist.md)
- **生成物はコミットする。** `assets/png/`・`assets/*.ico`・`packaging/msix/Assets/`。リポジトリに resvg のツールチェーンを持たない状態でもパッケージングできるようにするためで、[ADR 0060](../../v0.6/decisions/0060-msix-package.md) からの方針を引き継ぐ
- **20 / 28 / 40 の PNG が新しく増えた**（各面 2 種で 6 枚）。`src/tray.rs` が使うのは 16、`examples/egui_ime_probe.rs` が使うのは 32 で、それ以外は `.ico` の材料である
