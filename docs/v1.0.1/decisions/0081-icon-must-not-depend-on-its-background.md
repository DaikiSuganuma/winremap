# ADR 0081: アイコンは背景に依存しない絵にし、サイズは実 DPI から求める

- 作成日: 2026-08-17
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: **承認（オーナー指示 2026-08-17「白で塗ったバージョンで試してください」→ 実機確認「正常にアイコンが表示されていることを確認しました」）**
- 関連: [ADR 0080](0080-tray-icon-asks-for-the-small-metric.md)（トレイのアイコンは通知領域のサイズを指定して読む。**本 ADR がその背景の数値を訂正する**）、[ADR 0010](../../v0.1/decisions/0010-icon-embedding.md)（アイコンは exe に埋め込む。素材の正本は `assets/svg/`）、[ADR 0038](../../v0.2/decisions/0038-gui-win32-module.md)（`gui/win32.rs`）、[ADR 0060](../../v0.6/decisions/0060-msix-package.md)（MSIX パッケージ。資産は SVG から焼く）

## 背景

[ADR 0080](0080-tray-icon-asks-for-the-small-metric.md) でトレイに渡すアイコンのサイズを直した。トレイのアイコンにはキーが見えるようになったが、**「設定 > 個人用設定 > タスクバー > その他のシステム トレイ アイコン」の行は青い塗りつぶしのまま**だった。

推測をやめてオーナーのスクリーンショットの画素を測ったところ、原因は 2 つあり、どちらも ADR 0080 が扱ったものではなかった。

### 実測 1 — 描かれていたのは、そもそも我々の絵ではなかった

| 計測 | 値 |
|---|---|
| WinRemap の行の青領域 | 36 × 36（比 1.00） |
| Bluetooth の行の青領域 | 36 × 36（比 1.00） |
| WinRemap のアイコン素材の絵の比 | **1.40 : 1（横長）** |
| 行の台座の色 | `#007AD5` |
| WinRemap のアイコン本体の色 | `#0078D4` |

**設定アプリは各行のアイコンをアクセント色の角丸正方形の台座の上に描く。** Bluetooth は白いグリフ、Aqua Voice は明るい青の円なので台座の上でも見える。WinRemap は台座とほぼ同色で、しかもキーが**本体をくり抜いた穴**だった（`fill-rule="evenodd"` の単一パス）。穴から台座の同じ青が透け、絵全体が台座に溶けていた。

これは v0.8 の受け入れ P-4（オーナー報告 2026-08-09）で MSIX の `_altform-unplated` 資産を足して直した現象と**同じ性質**である。あのときはパッケージ資産の名前で解決したが、根っこ ——「絵の情報がアルファの抜きにしか無い」—— は残っていた。

### 実測 2 — 設定アプリが描いているのは、行の作成時に撮られた写真

行のレジストリ（`HKCU\Control Panel\NotifyIconSettings\<hash>`）は `IconSnapshot` という PNG を持つ。設定アプリが表示するのはこれで、**行が作られたときに一度だけ撮られ、アプリが新しいアイコンで再登録しても更新されない**。

| | 白っぽい画素 |
|---|---|
| 既存の行に入っていた `IconSnapshot` | **0**（＝旧素材） |
| 新しい 16px 素材 | 20 |

素材を直しても画面が変わらなかったのはこれが理由で、行を削除して作り直すと新しい絵になる。Explorer が行の状態をメモリに持つため、レジストリを消すだけでは足りず、Explorer の再起動を挟む必要がある。

### 実測 3 — ADR 0080 が挙げた寸法は、アプリが見ている値ではなかった

**winremap のプロセスは、トレイを組み立てる時点で `DPI_AWARENESS_UNAWARE` である**（`GetProcessDpiAwareness` で確認）。winit が DPI 認識を宣言するのはイベントループを作るときで、それは GUI スレッドで起動後に起きる。

したがってアプリの中では DPI 関連の API がすべて 96 dpi の値を返す。ADR 0080 が載せた「`SM_CXSMICON` = 24 / `SM_CXICON` = 48」は**DPI 認識のある別プロセス（PowerShell）で測った値**であり、アプリが見ているのは 16 / 32 だった。

その結果 ADR 0080 の変更は、150% の環境で渡す面を 32px から 16px にしていた。タスクバーが描くのは 24px なので、**縮小が拡大に変わっただけ**である。24px の枠に対する見え方を描き比べると、拡大が最も眠く、原寸が最良、縮小はほぼ原寸並みだった。

## 決定

### 決定 1 — キーは「抜き」ではなく不透明な白で塗る

`assets/svg/kbd-enabled.svg` を単一パス（evenodd）から 2 パスに分ける。本体を `#0078D4` で塗り、その上にキーを `#FFFFFF` で塗る。`kbd-disabled.svg`（`#8A8886`）も同じ。

**アイコンは、置かれる背景を知らない。** 明るいタスクバー、暗いタスクバー、アクセント色の台座 —— どれに置かれても読めることが要件であり、それはアルファの抜きでは満たせない。

### 決定 2 — サイズは `SetThreadDpiAwarenessContext` で実 DPI から求める

`gui/win32.rs` の `notification_icon_size` は、問い合わせの間だけ**このスレッドを** per-monitor 認識にし、主モニターの実効 DPI を得て `GetSystemMetricsForDpi(SM_CXSMICON, dpi)` を引き、直後に元の文脈へ戻す。プロセス全体と GUI には触れない。

実測でスナップショットが 24 × 24 になった。タスクバーが実際に描くサイズであり、拡縮が起きない。

### 決定 3 — 再生成を道具にする

`examples/app_icons.rs` を追加し、`cargo run --example app_icons` で SVG から `assets/png/*.png` 10 枚と `assets/kbd*.ico` 2 つを起こす。

ADR 0010 は「素材の正本は `assets/svg/`。変更時は PNG / .ico を再生成してコミットする」と決めたが、**再生成する道具は無く、外部ツールでの手作業だった**。絵を 1 回描き替えるだけで 2 面 × 5 サイズ ＋ .ico コンテナ 2 つを手で作り直すことになり、半分だけ更新される類の作業である。生成した `.ico` の各フレーム長は従来の手作りファイルと完全に一致した（16=1128、24=2440、32=4264、48=9640 バイト）。

## 理由

- **背景に依存しない絵は、どの表示面が増えても壊れない。** 台座を敷く面（設定アプリ）、敷かない面（タスクバー）、暗い面 —— 面ごとに手当てを足していく方式は、面が増えるたびに同じ不具合を再発する。v0.8 の P-4 がその 1 周目だった
- **スレッド単位の DPI 文脈なら、副作用の範囲が呼び出しの中で閉じる。** プロセス全体を認識にすると GUI の描画・座標系がすべて変わり、winit の設定とも競合しうる
- **道具があれば、素材と生成物が食い違わない。** 今回 SVG・PNG・.ico・MSIX 資産の 44 ファイルを一貫して起こせたのは道具があったからで、手作業なら MSIX の 30 枚は取り残されていた

## 却下した代替案

- **本体の色を台座と違う色に変える** — 台座は利用者のアクセント色でありうる。製品の色を Windows の設定に振り回されて決めることになる
- **プロセス全体を DPI 認識にする** — 決定 2 のとおり影響が広すぎる。GUI の見え方を変える判断は、それ自体で別に検討すべきもの
- **ADR 0080 を取り消して `from_resource(ordinal, None)` に戻す** — 32px 固定に戻ることを意味し、100% の環境では 16px 枠への縮小になる。原寸を出せるならその方がよい。ADR 0080 の**決定（サイズを明示する）は正しく、誤っていたのは背景に載せた数値**である
- **`IconSnapshot` をレジストリへ直接書いて既存の行を更新する** — 文書化されていない内部形式で、壊せば一覧そのものが壊れる。アプリが利用者のレジストリの表示状態を書き換えるのも筋が悪い
- **`LoadIconMetric(LIM_SMALL)` を使う** — DPI の根拠はプロセスの文脈であり、非認識のままでは 16 が返る。決定 2 と併用しない限り解決しない

## 影響・補足

- **⚠ ADR 0080 の「48 × 48 を渡して 24 へ縮小していた」は誤り。** 正しくは「32 × 32 を渡して 24 へ縮小していた」。ADR 0080 は書き換えず、訂正は本 ADR が持つ
- **既存の行は直らない。** `IconSnapshot` は作成時のもので、更新されない。MSIX を更新すればパスが変わって新しい行ができるため、次のリリースで自動的に新しい絵になる
- **プロセスが起動時に DPI 非認識であること自体は、トレイ以外にも効きうる。** `gui/win32.rs` のウィンドウアイコン（ADR 0038）も同じ `GetSystemMetrics` を使っている。今回は範囲を広げずトレイに閉じたが、別途見る価値がある
- **実測（2026-08-17）**: 作り直した行の `IconSnapshot` は 24 × 24、白い画素 52。トレイ・設定アプリの一覧とも、キーが見える状態を**オーナー確認済み**
- **受け入れ（v1.0 のチェックリストに入れる項目）**: ①トレイのアイコンにキーの隙間が見える ②無効にしたとき、灰色の面でも同じく隙間が見える ③設定 > 個人用設定 > タスクバー > その他のシステム トレイ アイコンで、行の名前が `WinRemap`（大文字の R）で、アイコンにキーが見える（**新規インストール後に確認すること** — 既存の行は古いスナップショットを持つ）
