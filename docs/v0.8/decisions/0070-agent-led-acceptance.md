# ADR 0070: 受け入れの対話は AI エージェントが司会する（ハーネスは道具に下ろす）

- 作成日: 2026-08-03
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: 採用（オーナー指摘 2026-08-03「AI エージェントと対話形式で質問するような形（プロンプト入力欄を利用）を想定していた。AI エージェントが全部お膳立てして、人間はそれの通り入力して報告する形」を受けた決定）
- 関連: [ADR 0069](0069-interactive-acceptance-harness.md)（**この ADR が置き換えるのは 0069 の「対話の主体」だけ**。読み書き先・4 値・環境の自動記録・置き場所・注入しないは 0069 のまま生きている）、[ADR 0053](../../v0.4/decisions/0053-test-inject-mode.md)（注入を受け付けるビルド。**受け入れでは使わない**）、[ADR 0063](../../v0.7/decisions/0063-symbol-keys.md)（記号キーは機械によって答えが変わる ＝ 打った刻印を記録に残す理由）、[v0.8 受け入れチェックリスト](../03_acceptance-checklist.md)
- 公式: [Claude Code の skills](https://code.claude.com/docs/en/skills)（`.claude/skills/<name>/SKILL.md` が `/<name>` になる）／[`Resolve-Path`](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/resolve-path)（.NET のカレントディレクトリは PowerShell の現在位置と別物）

## 背景

ADR 0069 は「受け入れテストは**対話形式で AI エージェントが環境を準備して、人間が入力し、その結果を選択できる**ような仕組みにしたい」というオーナー宣言から出た。実装は PowerShell の `Read-Host` による対話になり、**ADR 0069 自身がその帰結を書いていた**:

> **ハーネスは対話するので、AI エージェントからは実行できない**（標準入力が無い）。

**ここが読み違いだった。** 宣言が言う「対話」はこの会話欄（Claude Code のプロンプト入力欄）のことであり、AI エージェントは**司会をする側**である。`Read-Host` の実装は、AI エージェントを対話から締め出したうえで、その代役をターミナルに置いた。**主体が入れ替わっている。**

実際に v0.8 の受け入れを回そうとして、2 つの形で表面化した。

1. **エージェントが受け入れを進行できない。** 準備・提示・分類・記録のうち、エージェントができるのは準備だけになり、残りは人がターミナルの番号キーを押す作業になった。「全部お膳立てして、人は打って報告するだけ」からいちばん遠い
2. **人の言葉が 1 行のプロンプトに押し込まれた。** `Read-Host` は 1 問 1 答である。「色は変わるが、Zed の上では I ビームが見失いそうになる」のような**条件付きの報告**は、その場で聞き返して分解できる相手が要る

（同時に、相対パスで起動すると書き戻しだけが落ちる不具合も見つかった。`[IO.File]::ReadAllText` は**プロセス**のカレントディレクトリを見るので、`Test-Path` は通るのに `[IO.File]` はホームディレクトリを探していた。これは §影響で直した。）

## 決定

### 1. 司会は AI エージェント。スクリプトは**何も聞かない**

質問・提示・分類・確認は、すべてこの会話欄で行う。`run-acceptance.ps1` から `Read-Host` を全部外し、**非対話のコマンド群**にする。

| 呼び方 | すること |
|---|---|
| `<checklist>`（既定） | 一覧（`-Only` / `-Resume` で絞る） |
| `<checklist> -Show C-1,M-2` | 手順・通過条件・過去の記録 |
| `<checklist> -Prepare M` | 設定の退避と配置、WinRemap の起動、人に残る手順の表示 |
| `<checklist> -Record <file>` | 記録欄へ追記（環境は自動で刻む） |
| `-Teardown` | 実運用の設定を戻す（チェックリストを要らない） |
| `-Environment` | 記録に刻まれる環境の 1 行 |

**対話の実装が 1 か所になる**ことが眼目である。会話欄とターミナルの両方に対話があると、手順が 2 か所に存在する — [ADR 0069](0069-interactive-acceptance-harness.md) 背景 3 が、対話そのものについて再発することになる。

### 2. 進行の手順は**プロジェクトスキル** `/acceptance` に置く

[`.claude/skills/acceptance/SKILL.md`](../../../.claude/skills/acceptance/SKILL.md)。`/acceptance` で呼べる。

ADR に書いて毎回読ませる形も考えたが、ADR は**決定と理由**の記録であって手順書ではない。スキルなら**使うときだけ読み込まれ**、進行が回ごとにぶれない。何より、次に受け入れを回すエージェントが**この ADR を読み解いて手順を組み立て直さずに済む**。

### 3. 4 値は読み上げない。**人の言葉を、エージェントが分類する**

`Read-Host` は「[1] 通過 [2] 不合格 [3] 未実施 [4] 測れない」を人に選ばせていた。会話では**見えたことを言ってもらい、分類はエージェントが行い、書き戻す前に文面を見せて確認を取る**。

4 値そのもの（0069 決定 3）は変えない。変えるのは**誰がその写像を行うか**である。人にとって「不合格」と「測れない」の線引きは毎回考えるコストであり、機械が案を出して人が頷くほうが速い。**確認を取るまでが決定**であり、頷きが無いまま書き戻してはならない。

### 4. 記録の見出しは、**誰が答えたかを名乗る**

追記される見出しに `（対話: 人が実キーボードで確認し、AI エージェントが記録）` と入る。`-SelfTest`（旧 `-Answers`）を使った場合だけ `（**自己テスト。人は打っていない**）` になる。

書き戻す道具が「人が答えた」と主張する以上、**主張していることが文面に出ている**必要がある。0069 補足の「人が打っていないものを通過と書ける道具なので、痕跡が残らないと嘘の記録が作れてしまう」を、既定の側にも広げたものである。

### 5. 準備は**エージェントが実際に手を動かす**ところまで

`-Prepare M` は、設定の退避と配置に加えて **WinRemap を起動し直す**（トレイ →「再読み込み」を人に頼まない。再起動なら「そのプロセスが受け入れ用の設定を持っている」ことが疑いようがない）。

**ただし終了させるのは `-Exe` から起動したプロセスだけ**とする。オーナーがインストール版やパッケージ版を常駐させていることがあり、それは**このハーネスのものではない**。見つけたら「これは受け入れ対象ではない」と言って人に委ねる。

破壊的な準備（MSIX の登録・削除）を自動化しないのは 0069 決定 6 のまま。

### 6. 書き戻しは**区切りごと**

`C` / `M` / `S` / `P` の区切りが終わるたびに `-Record` する。**追記なので何回に分かれてもよい**（0069 決定 2）。最後にまとめて書く形だと、会話が途中で終わったときにその回の報告が全部消える — 会話は `finally` を持たないので、`Read-Host` 版より落ちやすいのはここである。

同じ理由で**後片付けはスキルの約束**にした。中断されたときも `-Teardown` を通してから返事をする。加えて、退避ファイルが残っていれば**どのコマンドも冒頭でそれを言う**ようにした（次の `-Prepare` は従来どおり拒む）。

## 却下した代替案

- **`Read-Host` 版も残す**（エージェント無しでも回せる経路）: 一見無害だが、**対話の手順が会話側とスクリプト側の 2 か所に存在し続ける**。受け入れは年に数回で、実施者は 1 人であり、その 1 人は Claude Code を開いて作業している。二重メンテの対価が無い
- **エージェントが 4 値を読み上げて番号で答えてもらう**: `Read-Host` を会話欄に移しただけで、人の作業は減らない。**分類はエージェントができる仕事**である
- **合否をエージェントが画面を見て判定する**: 0069 が既に却下している（それができる項目は `tests/ui` にある）。この ADR でも変えない — **人が見なければ分からない項目だけが残っている**
- **スキルではなく `CLAUDE.md` に手順を書く**: 常に読み込まれるので、受け入れをしない日の全セッションが手順書を抱えることになる
- **記録を会話ログから起こす**: 中間ファイルを挟まない点では魅力があるが、会話は要約で圧縮される。**追記の道具を通す**ほうが、書かれる文面を人が確認できる

## 影響・補足

- **相対パスの不具合を直した。** `[IO.File]::ReadAllText` は .NET プロセスのカレントディレクトリ（PowerShell を開いた場所）を見るため、`.\tests\acceptance\run-acceptance.ps1 docs\v0.8\03_acceptance-checklist.md` が `C:\Users\<user>\docs\...` を探して落ちていた。`Test-Path` と `Get-Content` は PowerShell の現在位置で解決するので、**解析までは通り、書き戻しだけが落ちる**という分かりにくい形だった。受け取った直後に `Resolve-Path` で絶対パスにする
- **`-Answers` は `-Record`＋`-SelfTest` になった。** 回答ファイルの形（`<id>|<結果>|<記録>`）は同じで、結果は 4 値の日本語でも `1`〜`4` でも書ける。空の記録・チェックリストに無い項目・4 値でない結果は**書き戻す前に落とす**
- **チェックリストと開発計画の記述を追随させた**（§1 の手順、§2.1 の事前準備、開発計画 §8 の 5）
- **ADR 0069 は取り消さない。** 5 つの決定のうち生きているのは 4 つで、置き換わったのは「対話の主体」だけである。0069 の背景（v0.7 で空いた 3 つの穴）と、それに対する答えは今も有効
