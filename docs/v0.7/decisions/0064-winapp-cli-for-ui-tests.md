# ADR 0064: UI テストの操作系を winapp CLI にし、エージェント版シナリオを廃止する

- 作成日: 2026-07-31
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／判断の根拠は §「実測」のとおり全数実測。ゲストからの撤去（§5）は**オーナー確認待ち**
- ステータス: 採用（§1〜§4）。§5 は提案
- 関連: [winapp CLI 移行検討](../../v0.5/notes/20260727_winapp-cli-migration.md)（検証計画。本 ADR はその Phase 1〜5 の結論）、[ADR 0053](../../v0.4/decisions/0053-test-inject-mode.md)（注入イベント受理モード。前提は変わらない）、[ADR 0055](../../v0.5/decisions/0055-accesskit-for-child-viewports.md)（子ビューポートを UIA に出す。これが無いと何も見えない）、[05_ui-test-automation.md](../../05_ui-test-automation.md)（運用手順）
- 実測: [v0.7 開発計画 §3.3.1・§3.4.1・§3.4.2](../01_development-plan.md)、[`tests/ui/guest/probe-winapp.ps1`](../../../tests/ui/guest/probe-winapp.ps1)（Phase 1 の測定スクリプト）
- 公式: [Windows App Development CLI](https://learn.microsoft.com/en-us/windows/apps/dev-tools/winapp-cli/)／[winappCli ui-automation.md](https://github.com/microsoft/winappCli/blob/main/docs/ui-automation.md)／[UI Automation](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-overview)

## 背景

UI テストは v0.4 から、ゲスト VM 上の Claude Code に **terminator MCP** を持たせ、英語のプロンプト（`tests/ui/scenarios/*.txt`）を読ませて操作・判定させる形だった。動いてはいたが、**不安定さが 3 層に分かれて残っていた**（[検証計画 §1](../../v0.5/notes/20260727_winapp-cli-migration.md)）。

| 層 | 中身 | v0.5 時点 |
|---|---|---|
| アプリ層 | 設定・ログウィンドウが UIA に出ない | **解決済み**（ADR 0055） |
| 操作層 | terminator の「クリック」は実体が座標クリックで、同じボタンが `Edit` **2/6**・`Clear` **2/4** しか当たらない | 未解決。押下をシナリオから外して回避していた |
| エージェント層 | LLM がツリーを読み違える／途中で止まる | 未解決 |

最も高くついていたのはエージェント層である。**エージェントが「アプリの不具合」と報告した 3 件が、すべて実測で否定された**（「インストールされていない」「プロンプトが文字化けしている」「Clear を押してもログが消えない」）。誤るだけでなく、**誤りの向きが「アプリのせい」に偏る**。テストの目的は退行を見つけることなので、この偏りは機能の欠陥そのものである。

## 決定

### 1. 操作と読み取りは winapp CLI で行う

`winapp ui inspect --json` / `search` / `get-property` / `invoke` / `wait-for` / `send-keys` を、ゲスト側の PowerShell から呼ぶ。ラッパーは [`tests/ui/guest/winapp-helpers.ps1`](../../../tests/ui/guest/winapp-helpers.ps1)。

根拠は全数実測である。

| 測ったこと | terminator | 素 UIA | **winapp** |
|---|---|---|---|
| `Edit` / `Clear` の押下（各 10 回） | 2/6・2/4 | 4/4 | **10/10・10/10** |
| 遷移待ち（固定 sleep 無し） | — | — | **10/10** |
| 起動をまたいだ要素の解決 | — | — | **3/3** |

winapp の `invoke` は座標クリックではなく **UIA のパターン駆動**であり、素 UIA と同じ経路を通る。「半分しか当たらない」は移行で消えた。

素 UIA でも同じ確度は出る（4/4）。それでも winapp を選んだのは、**素 UIA では書けないものが 2 つある**ためである。

- **`wait-for`** — egui はオンデマンド再描画なので、押下直後の読み取りが古い状態を返す。固定 `Start-Sleep` である限り原理的に不安定で、実際そこで揺れていた
- **トレイメニューの項目をコマンド ID で起動できる**（1001 有効/無効・1002 再読み込み・1003 設定・1004 ログ・1005 終了）。Win32 のポップアップ（`#32768`）は素 UIA でも terminator でも空の Pane にしか見えず、頭文字キー押下でしのいでいた。**頭文字は表示言語に依存し、`--lang ja` で成立しない**

### 2. エージェント版シナリオを廃止する

`tests/ui/scenarios/*.txt` と、ランナーの `claude -p` 実行経路を削除する。5 本すべてが移植され、**移植版が同じ判定をより速く、かつ再現して出す**ことを実測したためである。

| 検査 | チェック数 | 移植版（2 回以上一致） | エージェント版 |
|---|---|---|---|
| `01-settings-window` | 12 | 0:17（**5 回一致**） | 1:39 / 1:06 |
| `02-config-display` | 14 | 0:16 | 2:29 / 2:21 |
| `03-tray-actions` | 11 | 0:40 | 3:18 / 3:26 |
| `04-log-window` | 9 | 0:14 | 1:22 / 1:59 |
| `05-remap-notepad` | 10 | 0:30 | 3:34 / 1:19 |

速さは主目的ではない。**主目的は判定から LLM を外すこと**であり、それは達成された — 01 の 5 回連続実行では、判定が揃っただけでなく**採取した UIA ツリーの差分がステータスバーの `Started: <時刻>` 1 行だけ**だった。

さらに、移植版は**エージェント版より強い主張ができる**。05 は「置換パネルが開かなかった」で終わらず、WinRemap を止めて同じキーを同じ経路で送り、**パネルが開くことまで確かめる**。開かなかったことに意味があるのは、開くときに見えると分かっている場合だけである。これは判定がスクリプトだから足せた。

**失うもの**も書いておく。エージェントは「探索して何とかする」ことができた。今後、新しい検査は**人が書く**。GUI を変えたら `-DumpUia` で名前を採り直し、検査を直す手間が増える。それは払う。

### 3. 素の UIA 実装（`00-uia-actuation`）は対照として残す

移植版と重なるが消さない。**「winapp が間違っている」と「アプリが間違っている」を切り分けられる実装が他に無い**ためである。

この必要性は移行中に 2 度実証された。どちらも**こちら側のバグが「アプリの不具合」の形で報告された**。

| 時期 | 報告された内容 | 真因 |
|---|---|---|
| Phase 2 | 設定ウィンドウに `Edit` ボタンが無い（4 件） | PowerShell 5.1 は 1 件だけの一致で配列を剥がし、`PSCustomObject` に `Count` が無い。`return , $hits` で解決 |
| Phase 4 | リマッパーが無いのに置換パネルが開かない | 対照実験だけ `^h` を送っていた（効く綴りは `ctrl+h`）。パネルは開かなくて当然だった |

### 4. トレイ操作は「開くのは Win32、選ぶのは winapp」の混成にする

検証計画は「アイコンの昇格をやめてオーバーフロー経由にする」と想定していたが、**採らなかった**。winapp が可視トレイ（`Shell_TrayWnd`）を押せないのは「前面でないウィンドウは押さない」という**winapp の安全弁**であって Windows の制限ではなく、合成マウスイベントにその制限は無い。

| 段階 | 手段 |
|---|---|
| メニューを開く | 素の Win32 右クリック（`mouse_event`）。`promote-tray-icon.ps1` は**残す** |
| 項目を選ぶ | winapp `invoke <コマンド ID>` |

オーバーフローを使わないので、検証計画が挙げていた「chevron の `invoke` はトグルで 1 回おきに失敗する」問題も丸ごと消える。

### 5. ゲストから terminator MCP / Claude Code を外す（提案・未実施）

§2 でこのリポジトリからは呼ばれなくなった。ゲスト側の実体を消すと、**構造的な問題が 2 つ消える**。

1. **ゴールデンスナップショットの焼き付き。** 常駐 MCP サーバーがスナップショットに焼き付き、revert のたびに蘇る。`-AppProcessNames` で個別に対処してきたが、**そもそも常駐プロセスを置かなければ起きない**
2. **資格情報。** `CLAUDE_CODE_OAUTH_TOKEN` がゲストのユーザー環境変数に置かれている。この VM は複製され revert される。**トークンを置かないのが最も確実**

ただし実体の撤去とゴールデンの再取得は **windows-utility 側のプロビジョニング作業**であり、いま動いている既知良好なスナップショットを取り直す操作でもある。**本 ADR では提案にとどめ、実施はオーナーの判断を仰ぐ。**

## 受け入れた制約

| # | 制約 | 扱い |
|---|---|---|
| 1 | **winapp は public preview**。コマンド仕様が変わりうる | 読むのは `--json` のみ（テキスト出力は PowerShell 5.1 で CP932 として読まれ文字化けする）。`05` は `send-keys --help` を結果ファイルに毎回残す |
| 2 | **egui/AccessKit の要素に `AutomationId` が無い。** セレクタは名前頼み。スラッグ（`btn-...-7753`）は実行ごとに変わる | 名前で引き、必要なら `search --json` でスラッグに解決する。**UI 文言を変えるとテストが壊れる**ことを受け入れる |
| 3 | **`wait-for` は名前が 2 要素に一致すると「見つからない」と言う** | 一意な名前を使うか、スラッグに解決してから渡す |
| 4 | **キー送出は `--via send-input` が必須。** 既定の `post-message` はウィンドウメッセージで**低レベルフックを通らない** | ADR 0053（`--accept-injected`）の前提は変わらない。和音の綴りは `ctrl+h`。`^h` と `{Ctrl}h` は**終了コード 0 のまま文字として入る**ので、**押下は必ず効果で検証する** |
| 5 | 依存が 1 つ増える（winapp CLI がゲストに要る） | ゴールデンスナップショットに含める。バージョンは各検査が結果ファイルの先頭に記録する |

## 却下した案

| 案 | 却下理由 |
|---|---|
| **terminator のまま押下だけ素 UIA に逃がす**（v0.5 でやっていた形） | エージェント層が残る。誤判定が「アプリのせい」に偏る問題は押下とは別の層 |
| **`dump-uia.ps1` を育てて素 UIA だけで書く** | `wait-for` とトレイのコマンド ID が手に入らない。固定 sleep 依存とトレイの頭文字キー依存が残る |
| **エージェント版を並走させ続ける** | 同じ 5 件を 2 実装で維持することになる。比較の役目は `00-uia-actuation` が果たし、そちらは LLM のばらつきが無いぶん対照として上等 |
| **winapp で `send-keys` を使わず全部 keybd_event にする** | 実測で `send-keys --via send-input` が通った。フォールバックとしては残す（両方が同じ結果を出すことを毎回確かめている） |

## 影響

- `tests/ui/scenarios/` を削除。`run-vm-ui-test.ps1` から `claude -p` 経路・プロンプトの直書き・`# needs:` / `# timeout:` ディレクティブ処理が消える
- ゲスト側の検査スクリプトを**検査名と同じファイル名**に揃えた（`winapp-settings-window.ps1` → `01-settings-window.ps1` など）。`-winapp` の接尾辞は「エージェント版と区別するため」の名前で、区別すべき相手が無くなった
- ランナーの引数は `-Check`（`-Scenario` は別名として残す。過去の受け入れチェックリストがその名前で書かれている）
- ペイロードは `guest\*.ps1` と `fixtures\*.toml` を**ディレクトリごと**送る。手書きの一覧は検査を足すたびに古くなり、**コピーし忘れた検査は「結果ファイルが無い」という何も言わない ERROR** になっていた
