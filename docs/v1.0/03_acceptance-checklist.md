## 0. この文書の目的

**v1.0 は「使っていて気づいたことを直した版」である**（[開発計画 §2](01_development-plan.md)）。5 件すべてがオーナーの実地の報告から始まっている。したがってこの受け入れは、

1. **直したものが直っていること** — M-2（拡大表示で I ビームに色が付かない）と F-5（長いパスでボタンが窓の外）
2. **増えたものが増えたとおりに動くこと** — F-1〜F-4（設定ファイルの記憶とトレイの表示）
3. **これまでどおり動くこと** — C-1〜C-5・M-1〜M-7・H-1〜H-10・P-1〜P-10 を継承する

### ⚠ この版で特に注意すること

- **拡大表示（125% 以上）の画面で測ること。** これがこの版の最重要の制約である。[ADR 0076](decisions/0076-read-cursors-unscaled.md) の不具合は**拡大率 100% では原理的に再現しない** — 修正前のバイナリでも通ってしまう。**3 版にわたって捕まらなかった理由がそれである**（計測しうる場所がすべて実質 DPI 非対応だった）。画面の拡大率を確かめてから始めること
- **M-2 の通過条件が変わった。** v0.8・v0.9 は「**何も描かれないカーソルにならない**」を見る項目だった。原因が特定された今、見るのは「**I ビームにちゃんと色が付く**」である。**付かなければ、それは 0.9.0 と同じ症状が残っているということ**
- **設定ファイルが増えている前提の版である。** F-1〜F-4 は**フォルダーに `*.toml` が 2 本以上ある**ことを前提にする。準備は [§4.1](#41-事前準備) にある
- **P-9 の更新元は 0.9.0 である。** Store 版 0.9.0 が機械に入っている状態から始めること。[§7.2](#72-store-側p-8p-9) を先に読む
- **リリースビルドで通す。** 版番号が **1.0.0** と出ることを、ログのセッション行かトレイのメニュー先頭で確かめてから始める

## 1. 毎リリースの手順

```powershell
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --features test-inject -- -D warnings
cargo test                              # 160 件（v0.9 の 142 件から 18 件増えた）
.\site-src\build.ps1 -Check             # site/ が site-src/ から作った通りか（ADR 0066）
cd tests\ui
.\run-vm-ui-test.ps1                    # ゲスト VM での UI 自動テスト一式
cd ..\..
cargo build --release --features test-inject
.\tests\acceptance\probe-ime-cursor.ps1 # カーソルの画素を直接読む検査（10 項目、ADR 0067・0073・0076）
cargo build --release                   # 受け入れは素の配布ビルドで行う
```

**自動側は Claude Code が回す。** 所要は v0.9 の実測（全体で 30 分強、うち 26 分が VM）から大きく変わっていない。

| 手順 | 所要 | 人の作業を邪魔するか |
|---|---|---|
| `cargo fmt --check` / `clippy` / `cargo test` | 合わせて 30 秒ほど | しない（CPU は使う） |
| `site-src\build.ps1 -Check` | 2 秒 | しない |
| `run-vm-ui-test.ps1` | **26 分**（v0.9 実測） | **少し邪魔する** — VMware のウィンドウが開く |
| `cargo build --release [--features test-inject]` | 25〜40 秒ずつ | しない。**WinRemap が `target\release` から常駐しているとビルドが「アクセスが拒否されました」で落ちる** — トレイから終了してから流す |
| **`probe-ime-cursor.ps1`（10 項目）** | 1 分前後 | **強く邪魔する。下記** |

**`probe-ime-cursor.ps1` の間は機械に触らないこと。** セッション全体のマウスカーソルを差し替え、メモ帳と `winver` を開いて前面を何度も奪い、IME を切り替える。**人が前面を動かすと検査のほうが誤る**ので、その回はやり直しになる。

## 2. カーソルまわり（M-1〜M-7）

### 2.1 事前準備

**`-Prepare M`。** 設定は [`tests/acceptance/ime-cursor.toml`](../../tests/acceptance/ime-cursor.toml)。退避・配置・起動・後片付けはハーネスがやる。**メモ帳と、暗い背景のアプリ（Zed など）を開いておくこと。**

**そして画面の拡大率を確かめること**（設定 → システム → ディスプレイ → 拡大／縮小）。**125% 以上でなければ、M-2 はこの版の主題を測っていない。**

### 2.2 項目

**M-1・M-3〜M-7 は [v0.9 §2.2](../v0.9/03_acceptance-checklist.md#22-項目) と同一。M-2 は通過条件を書き換えた。**

| # | 何を見るか | 手順 | 通過条件 |
|---|---|---|---|
| **M-1** | **IME のオン・オフで色が変わる** | メモ帳で IME をオンにし、マウスを動かす。オフに戻す | ①オンで**矢印に色が付く** ②オフで**素に戻る** ③切り替えてから色が変わるまでが**待たされる感じでない** |
| **M-2** | **入力欄の上でも変わる**（I ビーム）— **この版の主題** | 同じ状態で、テキストの上へマウスを乗せる。**そのあと、しばらく普通に使う** | ①**I ビームにも色が付く**（0.9.0 では拡大表示で付かなかった） ②**黒い四角にならない**（形が残っている） ③**暗い背景のアプリ**でも見失わない（白い縁が効いている） ④何も描かれないカーソルにならない |
| **M-3** | **管理者権限のウィンドウの上では変わらない** | 管理者権限のターミナルを前面にして IME をオン | **色は変わらず、パネルも出ない**（UIPI） |
| **M-4** | **強制終了すると色が残り、次の起動で戻る** | 色が付いた状態で `Stop-Process -Name winremap -Force`。そのあと起動し直す | ①**色が残る** ②トレイに居ないことと合わせて「異常終了した」と読める ③**起動し直すと戻る** |
| **M-5** | **独自のカーソルテーマが保たれる** | テーマやサイズを変えている場合、色を付けてから戻す | ①色付きでも**自分のテーマの形** ②戻したあと元に戻る。**変えていなければ「未実施」** |
| **M-6** | **パネルを出さずにカーソルだけ使える** | `enabled = false` ＋ `change_cursor_color = true` で再読み込み | ①「あ」パネルは出ない ②カーソルの色は変わる |
| **M-7** | **設定ウィンドウでカーソルの色を編集できる** | トレイ → 設定 → `[ime_indicator]`。表示を見てから「編集」に入り、`enabled` のチェックを外す | ①表示・編集の**両方**に 2 行がある ②`enabled` を外しても**消えない** ③色の欄が `#rrggbb` で**見本**が隣に出る ④保存せずに閉じても元の値のまま |

> **M-2 が落ちたら、ログの `カーソル:` の行を見ること。** 「**元が空だったので着色しなかった**」と出ていれば、[ADR 0076](decisions/0076-read-cursors-unscaled.md) が塞いだはずの経路をまだ通っている。そのログを添えて記録すること。
>
> **自動側の裏取りがある。** `probe-ime-cursor.ps1` の `the-i-beam-keeps-its-shape`（着色されているか）と、この版で足した復元側 4 か所（**カーソルがそこに在るか**）。**手動と自動が食い違ったら、両方を記録に書く** — 片方だけ正しいことがこの不具合の性質だった。

## 4. 設定ファイルの選択と表示（F-1〜F-5、**この版で新設**）

### 4.1 事前準備

**`-Prepare F`。** ハーネスは**設定フォルダーに `*.toml` を 2 本**用意する（既定の `config.toml` と、キーマップ件数が違うもう 1 本）。件数が違うのは、どちらが効いているかを**トレイのツールチップとログの件数で見分けられる**ようにするためである。

> **`%APPDATA%\winremap\last-config.txt` を退避すること。** この版で増えたファイルで、F-1〜F-3 はこれを書き換える。ハーネスが退避・復元する。

### 4.2 項目

| # | 何を見るか | 手順 | 通過条件 |
|---|---|---|---|
| **F-1** | **前回選んだファイルで起動する** | 設定ウィンドウのアドレスバーでもう 1 本へ切り替え → トレイから**終了** → もう一度起動する | ①起動直後に**切り替えた側**が読まれている（ログの `前回選ばれた設定ファイルを開きます` と、キーマップ件数） ②トレイのツールチップの件数が一致する |
| **F-2** | **`--config` はその 1 回の指示** | F-1 のあと、`.\winremap.exe --config <既定の config.toml>` で起動する。終了して、**引数なしで**もう一度起動する | ①`--config` で指した方が読まれる ②**記憶の行は出ない** ③**引数なしの次の起動では、また F-1 で選んだ方に戻る**（`--config` が記憶を書き換えていない） |
| **F-3** | **記憶したファイルが消えたら既定へ戻る** | F-1 で選んだ側の `.toml` を退避（削除）してから起動する | ①既定の `config.toml` が読まれる ②ログが**探しに行った名前を言う**（`前回選ばれた設定ファイルがありません（…）`） ③起動が失敗しない |
| **F-4** | **トレイのメニューが、いま効いているファイル名を出す** | タスクトレイのアイコンを**右クリック**する。次に設定ウィンドウで別のファイルへ切り替え、**もう一度右クリック**する | ①バージョンの下に**ファイル名の行**がある ②切り替えると**次に開いたメニューの表示も変わる** ③**壊れた `.toml` へ切り替えて読み込みに失敗したときは、古い方の名前のまま**（効いているキーマップは古い方なので） |
| **F-5** | **長いパスでもボタンが窓の中にいる** | 深いフォルダーの設定で設定ウィンドウを開き、**窓の幅を狭くしていく**。パスの上にマウスを乗せる | ①**ファイルのプルダウン・↻・編集がいつも窓の中**にいる（押せる） ②パスが**幅に応じて伸び縮み**する（先頭と末尾が残り、途中が `…`） ③省略されているとき、**ツールチップで全体が読める** |

> **F-4 ③ は壊れた `.toml` を用意する必要がある。** ハーネスが `broken.toml`（[`tests/ui/fixtures/broken.toml`](../../tests/ui/fixtures/broken.toml) と同種）を置く。**リマップは止まらない**のが正しい挙動である（[ADR 0050](../v0.4/decisions/0050-config-file-switching.md) 決定 3）。
>
> **F-1 と F-4 ②は同じ操作で見られる。** 続けて回すと 1 回の切り替えで両方が測れる。

### 7.2 Store 側（P-8・P-9）

1.0.0 の認定通過後にしか測れない。**認定を待つ間にリリースを止めない** — 通過後に `-Resume` で埋める。

**通過後は P-9 → P-8 の順で行う。** P-8 は**アンインストールして新規インストールする**項目なので、先に通すと **P-9 が要求する「0.9.0 が入っている状態」が消える**。Store は旧バージョンを配らないので、**更新経路は二度と測れなくなる**（v0.7 で 1 度実際に起きた）。

**その日の最初の作業として P-9 を回すこと。** Microsoft Store の「アプリの更新」を切るには管理者権限が要り、オーナーの権限では切れなかった（2026-08-10）。**切れない機械では、通過の連絡を見たら他の何よりも先に、ライブラリから手で更新するしかない。**

**更新前に自動起動をオンにしておくこと。** 通過条件④は「自動起動の設定が保たれる」だが、**既定のオフのままでは何も測れない**。
