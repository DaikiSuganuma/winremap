# ADR 0079: トレイのメニューは、いま効いている設定ファイルの名前を出す

- 作成日: 2026-08-16
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: **承認（オーナー指示 2026-08-16「タスクトレイから右クリックしたときのメニューに、現在読み込んでいるファイル名を表示してほしい」）**
- 関連: [ADR 0050](../../v0.4/decisions/0050-config-file-switching.md)（設定ファイルの切り替え）、[ADR 0077](0077-remember-the-chosen-config-file.md)（選んだ設定ファイルを次回の起動へ引き継ぐ）、[ADR 0007](../../v0.1/decisions/0007-tray-crate-tray-icon.md)（トレイは `tray-icon` クレート）、[ADR 0040](../../v0.2/decisions/0040-menu-icons-rasterized-at-build-time.md)（メニューアイコンは build.rs で焼く）

## 背景

トレイのメニューの先頭は `WinRemap v0.9.0` という無効化された見出しだった。「何を動かしているか」の半分しか答えていない。

**設定ファイルは 1 つではない。** [ADR 0050](../../v0.4/decisions/0050-config-file-switching.md) 以降、設定ウィンドウのアドレスバーでフォルダー内の `*.toml` を切り替えられ、[ADR 0077](0077-remember-the-chosen-config-file.md) からはその選択が次の起動にも効く。つまり**起動した WinRemap がどのファイルで動いているかは、もう「既定の config.toml」と決め打ちできない**。

常駐アプリに対して「いま何で動いている?」と尋ねる場所は、トレイのメニューである。

## 決定

### 決定 1 — バージョンの見出しの下に、ファイル名の見出しをもう 1 行置く

```
[アイコン] WinRemap v0.9.0
[書類]     personal-ja.toml
------------------------------
           有効
...
```

バージョンと同じく**無効化された見出し**（押せない）。2 行で「どのプログラムか」「どの設定か」を答える。

### 決定 2 — 出すのは**ファイル名だけ**で、フォルダーは出さない

「どこにあるか」に答えるのは設定ウィンドウのアドレスバーであり、そちらは長いパスを省略しなければならないほど長い（[ADR 0078](0078-address-bar-elides-the-path.md)）。MSIX 版のフォルダーをメニューに置くと、メニューが画面幅を争いはじめる。

### 決定 3 — 書き換えるのは**読み込みに成功したときだけ**

`Tray::reload` の成功側で `set_text` する。失敗側では触らない。

切り替えに失敗したときの意味論は [ADR 0050 決定 3](../../v0.4/decisions/0050-config-file-switching.md) が決めている — **ライブの表は据え置き、パスは切り替わったまま**。このとき効いているキーマップは**古いファイル**のものなので、新しいファイルの名前を出すのは「現在読み込んでいる」の唯一の嘘になる。

起動時の初期値も同じ理由で `main` が読み込みを終えたあとの使用中パスから採る（`tray::init` はその後に呼ばれる）。

## 理由

- **状態を新しく持たない。** 名前は使用中パス（`gui::active_config_path()`、ADR 0050 決定 1 の唯一の正）から都度求める。トレイ側にコピーを持つと、切り替えのたびに同期が要る
- **書き換える場所が、ツールチップを書き換える場所と同じ 1 か所。** 「キーマップ N 件」のツールチップ更新の隣に置いたので、片方だけ古くなる余地がない
- **アイコンは既存の仕組みに乗る。** `file-earmark-text` を `MENU_ICONS` に足すだけで、build.rs が 16×16 の RGBA に焼く（ADR 0040）。設定ウィンドウが同じ絵を使っている

## 却下した代替案

- **バージョンの行に足す**（`WinRemap v0.9.0 — personal-ja.toml`） — 1 行に 2 つの答えが混ざる。バージョンだけを見たい場面（不具合報告）で読みにくくなる
- **「設定を再読み込み」の項目に括弧書きで足す** — その項目は動作であって状態ではない。押す前に読むものと、押したら起きることが混ざる
- **フォルダーのパスも出す** — 決定 2 のとおり
- **キーマップ件数も出す** — ツールチップ（`WinRemap — キーマップ N 件`）が既に言っている。メニューは開かないと読めないので、常に見えるツールチップの方が向いている
- **使用中パスを常に映す（読み込み失敗時も）** — 決定 3 のとおり、それは「読み込んでいる」ではなく「選ばれている」であり、キーマップの実態と食い違う

## 影響・補足

- **⚠ メニュー項目は「見せたい位置」ではなく「最後」に作ること。** `muda` はコマンド ID を**作成順**に振り、UI テストはメニューを**ID で叩く**（`1003` が「設定」。ゲストの表示言語に依存しないための設計、[ADR 0064](../../v0.7/decisions/0064-winapp-cli-for-ui-tests.md)）。**見せる位置で作ったところ、以降の ID が 1 つずつずれ、VM の 10 件中 6 件が「別の項目を叩いて、叩けたことは成功と報告する」状態になった**（2026-08-16 に実測）。並び順は `append_items` が決めるので、作成順とは自由に食い違ってよい。実測で確認した並びと ID:

  | 位置 | ID | 項目 |
  |---|---|---|
  | 0 | 1000 | `WinRemap v1.0.0` |
  | 1 | **1006** | **`config.toml`（この版で追加。最後に作る）** |
  | 3 | 1001 | 有効 |
  | 5 | 1003 | 設定 |
  | 6 | 1002 | 設定を再読み込み |
  | 7 | 1004 | ログを表示 |
  | 9 | 1005 | 終了 |


- **実測（2026-08-16）**: 起動直後のメニューは `config.toml`、設定ウィンドウで `personal-ja.toml` へ切り替えて再起動したメニューは `personal-ja.toml`。**オーナー確認済み**
- **受け入れ（v1.0 のチェックリストに入れる項目）**: ①トレイの右クリックにファイル名が出る ②ウィンドウで切り替えると、次に開いたメニューの表示も変わる ③壊れたファイルへ切り替えて失敗したときは、**古い方の名前のまま**である
