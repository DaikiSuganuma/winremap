# ADR 0078: アドレスバーのパスは、行が測った残り幅に合わせて省略する

- 作成日: 2026-08-16
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: **承認（オーナー指示 2026-08-16「パスが長いとウィンドウからはみ出す。ウィンドウの横幅に応じて省略したい」）**
- 関連: [ADR 0050](../../v0.4/decisions/0050-config-file-switching.md)（設定ファイルの切り替え）、[画面設計書 §2](../../v0.4/04_config-editing-screens.md)（アドレスバー）、[ADR 0064](../../v0.7/decisions/0064-winapp-cli-for-ui-tests.md)（UI テストを winapp CLI で駆動する）

  - [`egui::UiBuilder::sizing_pass`](https://docs.rs/egui/0.36.1/egui/struct.UiBuilder.html#method.sizing_pass)（**却下**。理由は後述）

## 背景

設定ウィンドウのアドレスバーは `📁 <フォルダーのパス> › [ファイル ▾] [↻] … [編集]` という 1 行である。**このうちフォルダーのパスだけ、長さに上限が無い。**

egui の水平レイアウトは押し返さない。行に収まらない分は、後ろの部品がウィンドウの外へ出ていくだけである。2026-08-16 に実測した状態（ウィンドウ右端 x=1778）:

```
[ComboBox]  x=1759..1963   ← ファイルのプルダウンが右端をまたいでいる
[Button 編集] x=1948..2063  ← 完全に外
```

**押せないボタンになる。** MSIX 版の設定フォルダー（`%LOCALAPPDATA%\Packages\…\LocalCache\Roaming\winremap`）や、一時フォルダーの下は普通にこの長さになる。

## 決定

### 決定 1 — 省略は「先頭と末尾を残し、途中を `…` にする」

`C:\…\scratchpad\appdata\winremap` の形。人が読むのは**どのドライブか**と**どのフォルダーか**の 2 つで、`AppData\Local\Temp\…` のような途中は最も長く、最も何も言わない。

末尾は「入る限り深いところまで」残す。窓を広げたときに増えるのは末尾側で、途中が復活するのではない。

ドライブと最深フォルダーすら入らない場合は、ドライブも落として**フォルダー名を頭から食う**（`…remap`）。兄弟フォルダーを見分けるのは名前の末尾だからである。

省略が起きたときは、**元のパス全体をツールチップに出す**。

### 決定 2 — 残り幅は、その行自身が**測る**（前フレームの実測値を使う）

パスに使ってよい幅は「行の幅 − パス以外が使った幅」である。この「パス以外」を**予測しない**。予測は行のもう 1 つの記述（「アイコンと山かっこと プルダウンと ボタン 2 つと 隙間 6 つ」）になり、**次にボタンが 1 つ増えた日に食い違う**。

代わりに `address_row` が自分の実測値を返す:

```
右端のボタンの右辺 − 行の左辺 − パスの幅 − 余白 = パス以外が使った幅
```

これを次のフレームが使う。パス以外の部品はパスが何であっても同じなので、この値は安定している。**遅れは 1 フレームだけ**で、ウィンドウを開いた瞬間とリサイズ中がそれに当たる。

### 決定 3 — 右端のボタンは、明示的な余白で右端へ寄せる

`Layout::right_to_left` の入れ子をやめ、`add_space(余り)` を挟んで左から右へ 1 本で並べる。余りは決定 2 の数値から出るので、行の並び順とコードの並び順が一致し、「保存・元に戻す」も読み順のまま書ける（画面設計書 §2.4）。

## 理由

- **省略の規則は純粋関数（`elide_path`）にした。** 幅の測り方を引数（クロージャ）で受け取るので、フォント無しでテストできる。1 文字 1.0 として「どの文字が残るか」を 5 件のテストで固定した — 収まる場合・深いパス・絶望的に狭い場合・区切りの無い名前・**日本語のフォルダー名**（文字境界で切らないと panic する）
- **1 フレームの遅れは、この画面では見えない。** アドレスバーはリサイズ中も毎フレーム描き直され、収束は 1 フレームで終わる

## 却下した代替案

- **`UiBuilder::sizing_pass().invisible()` で、パス抜きの行をもう一度並べて測る**（最初に実装し、動かしてから捨てた）。正確で 1 フレームの遅れも無いが、**測定用のウィジェットが UI オートメーションの木に現れる**。実測（2026-08-16、UIA で列挙）:

  ```
  [Image] '' / [Text] '›' / [ComboBox] '' / [Button] '' / [Button] '編集'   ← 測定用の複製
  [Image] '' / [Text] '…p' / [Text] '›' / [ComboBox] '' / [Button] '' / [Button] '編集'
  ```

  egui はウィジェットの id ごとに AccessKit のノードを作り、**不可視・無効の子でも作る**。この画面は UI テストが UIA で駆動しており（ADR 0064）、「最初に見つかった `編集` ボタン」が押しても何も起きない方だという事態を招く。**測定のために画面の外側の見え方を汚さない**
- **各部品の幅をテーマ定数とグリフから見積もる** — 決定 2 のとおり、行の 2 つ目の記述になる
- **パスのラベルを `truncate()` に任せる** — egui の truncate は「使える幅いっぱいまで」であり、水平レイアウトでの「使える幅」は行の残り全部なので、後ろの部品は結局押し出される。末尾が消えるのも、パスとしては読みたい側が消える
- **パスを 2 行にする / ウィンドウの最小幅を上げる** — 1 行の帯という画面設計（§2）を、長いパスのためだけに変えることになる

## 影響・補足

- `ConfigWindow` に `header_reserved: f32` が 1 つ増えた（前フレームの実測値）
- **受け入れ（v1.0 のチェックリストに入れる項目）**: 深いフォルダーの設定でウィンドウを狭くしていき、①プルダウン・↻・編集がいつも窓の中にいること ②パスが幅に応じて伸び縮みすること ③省略時にツールチップで全体が読めること
