# ADR 0077: 設定ウィンドウで選んだ設定ファイルを、次回の起動へ引き継ぐ

- 作成日: 2026-08-16
- 作成: Claude Code（AI モデル: claude-opus-5[1m]）／レビュー・承認: オーナー
- ステータス: **承認（オーナー指示 2026-08-16「起動したときに、前回使用していた toml で設定を読み込むようにしてください」）**
- 関連: [ADR 0050](../../v0.4/decisions/0050-config-file-switching.md)（設定ファイルの切り替え）、[ADR 0061](../../v0.6/decisions/0061-packaged-config-path.md)（MSIX の `%APPDATA%` 解決）、[ADR 0059](../../v0.6/decisions/0059-first-run-creates-the-default-config.md)（初回起動で既定の設定ファイルを作る）
- 公式: [Behind the scenes of an MSIX package — AppData operations](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)

## 背景

[ADR 0050](../../v0.4/decisions/0050-config-file-switching.md) 以来、設定ウィンドウのアドレスバーで**使用中の設定ファイルを隣の `*.toml` へ切り替えられる**。しかしその選択は**プロセスと同じ寿命しか持たない** — 次の起動は既定の `config.toml` に戻り、画面には何も出ない。

これは仮の話ではなく、オーナーの日常である。0.9.0 のログ（2026-08-15）に、その 1 往復がそのまま残っている。

```
2026-08-15 11:42:23  WinRemap v0.9.0 を起動しました
設定ファイル: ...\config.toml（キーマップ 1 件）
11:42:53  設定ファイルを切り替え: personal-ja.toml
```

**毎回の起動で、同じ切り替えをやり直している。** サインインのたびに、キーが「昨日と違う」状態で立ち上がり、直す操作を覚えていないと原因も分からない。

## 決定

### 決定 1 — 記憶するのは「設定ウィンドウで選んだ」ときだけ

アドレスバーの切り替えは `gui::choose_config_path` を通り、そこが**使用中パスの差し替えと記憶の書き込みを両方行う**。起動時のパス設定（`gui::set_config_path`）はここを通らない。

**`--config` が指したパスは記録も参照もしない。** これは「その 1 回の実行」への指示であり、選択ではない。受け入れプローブは 1 回の実行で使い捨ての設定ファイルを指して WinRemap を 2 回起動するし、検証のための一時的な起動も同じ形をとる。それが次回の起動を乗っ取ってはならない。

記録しないのは**コマンドラインが指したパス**であって、その実行が丸ごと除外されるわけではない。`--config` で起動した WinRemap でも、ウィンドウでファイルを選び直せばそれは記録される — 選択はどちらの起動の仕方でも選択である。

### 決定 2 — 記憶は、既定の設定ファイルの隣に置く 1 行のテキスト

`%APPDATA%\winremap\last-config.txt`。中身は選ばれたファイルの**絶対パス 1 行**。

- **設定ファイルの中には書かない。** 「どの設定ファイルを開くか」は、まだ選ばれていない設定ファイルには答えられない（循環する）。加えて `*.toml` は利用者が手で書くファイルであり、コメントごと保持する編集経路がすでにある — そこへ機械が別種の情報を混ぜない
- **置き場所は使用中ファイルの隣ではなく、既定の設定ファイルの隣。** `--config D:\work\keys.toml` の隣に置くと、次の素の起動（`%APPDATA%` を見る）は永久にそれを見つけられない
- **MSIX でも同じ解決を通す**（ADR 0061）。パッケージ内では `%APPDATA%` の 2 つの綴りが別のファイルを指し、存在するのは片方だけである

### 決定 3 — 記憶が使えないときは既定に戻り、その理由をログに書く

`recall` の答えは 3 つ。

| 状態 | 起動時の動き | ログ |
|---|---|---|
| 記憶が無い・空・相対パス | 既定のパス（1.0.0 より前と同じ） | 何も言わない |
| 記憶したファイルが**消えている** | 既定のパス | 「前回選ばれた設定ファイルがありません（パス）。既定の設定ファイルを使います」 |
| ファイルがある | そのファイルを開く | 「前回選ばれた設定ファイルを開きます: パス」 |

**消えている場合を「記憶が無い」と一緒にしない。** 設定ファイルの名前を変えた利用者から見ると、キーマップが黙って元へ戻る現象になる — 探す手がかりが要る。

相対パスを受け付けないのは、常駐アプリの作業ディレクトリ（ショートカット、自動起動）が**利用者が何かを選んだ場所ではない**ため。

### 決定 4 — 記憶の書き込みに失敗したら、そう言う

`gui::log::emit` で報告する。ここで起きた失敗は**次回の起動まで見えない**（古いファイルが開く）ので、黙って捨てると、この機能が消そうとしている混乱をそのまま作り直すことになる。

## 理由

- **触る場所が 2 か所で済む。** 起動時のパス決定 1 か所と、切り替え 1 か所。読み込み・検証・atomic swap・失敗時の据え置きは、いずれも既存の経路のまま（ADR 0050 決定 2 と同じ考え方）
- **失敗が起動を止めない。** 記憶に関わるすべての失敗は「記憶が無い」に落ち、1.0.0 より前の挙動になる
- **利用者が消せる。** `last-config.txt` は設定フォルダーに見える普通のテキストで、削除すれば既定に戻る。名前がそれ自身の説明になっている
- **単体テストで固定できる。** `recall` / `remember` はファイルを触るだけの純粋な操作なので、ライブラリ側（`winremap::config::last_used`）に置いて 6 件のテストを付けた — 往復、消えたファイル、記憶なし、使えない中身 4 種、手で編集された形（CRLF・末尾の空行）、上書き

## 却下した代替案

- **`config.toml` に `last_used = "..."` を書く** — 決定 2 のとおり循環する。利用者のファイルを機械が書き換えることにもなる
- **`--config` も記憶する** — 使い捨ての設定を指した 1 回の起動が、次の起動を乗っ取る。プローブが毎回それをやる
- **レジストリに書く** — WinRemap はレジストリを使わない。ポータブル運用（`%APPDATA%` ごと持ち歩く）と噛み合わず、アンインストール後に残る
- **記憶したファイルが「壊れている」ときに既定へ自動で戻す** — [ADR 0050 決定 3](../../v0.4/decisions/0050-config-file-switching.md) と同じ理由で却下。見えないところで別のファイルに切り替わるより、エラーを見せて利用者に委ねる方が既存の失敗モデルと一貫する。逃げ道は `--config`。**ファイルが存在しない**場合だけは、開く対象そのものが無いので既定に戻る（決定 3）
- **起動時に「前回のファイルを使いますか」と尋ねる** — 常駐アプリの起動に対話を挟むことになる。選択はすでに設定ウィンドウで行われている

## 影響・補足

- **WinRemap が書くファイルが 1 つ増える。** `src/gui/mod.rs` の「`config.toml` しか書かない」という記述を更新した。ログをファイルに書かない不変条件（AGENTS.md 6）には触れていない — 記録するのはパス 1 本である
- **`--help` の `-c, --config` の既定値の説明を書き換えた**（「設定ウィンドウで最後に選んだファイル。無ければ `%APPDATA%\winremap\config.toml`」）
- **受け入れ（v1.0 のチェックリストに入れる項目）**: ①ウィンドウで切り替え → 終了 → 起動で同じファイルが開く ②`--config` で起動しても記憶は書き換わらない ③記憶したファイルを消すと既定に戻り、ログがその名前を言う
