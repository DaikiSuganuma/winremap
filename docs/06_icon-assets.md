## 1. いちばん大事なこと

**`assets/png/` と `assets/*.ico` と `packaging/msix/Assets/` は生成物である。手で編集してはならない。** 次に再生成コマンドを流した人が、気づかずに上書きする。

**正本は `assets/svg/` の 4 つだけ**（うち 2 つは未作成）。

```
assets/svg/kbd-enabled.svg          有効・通常サイズ用   ← 正本
assets/svg/kbd-disabled.svg         無効・通常サイズ用   ← 正本
assets/svg/kbd-enabled-small.svg    有効・小サイズ用     ← 正本（任意。無ければ上で代用）
assets/svg/kbd-disabled-small.svg   無効・小サイズ用     ← 正本（任意）
```

---

## 2. なぜマスターが 2 組あるのか

Windows は**表示スケールに応じて別々のサイズを要求する**。通知領域（タスクトレイ）が要求するのは `SM_CXSMICON` で、これは 16 px にスケールを掛けた値である。

| 表示スケール | トレイ（`SM_CXSMICON`） | 大アイコン（`SM_CXICON`） |
|---|---|---|
| 100% | **16** | 32 |
| 125% | **20** | 40 |
| 150% | **24** | 48 |
| 175% | **28** | 56 |
| 200% | **32** | 64 |

**トレイが 48 px を要求することはない。** 48 が効くのはエクスプローラーの大アイコン表示・Alt+Tab・ウィンドウの大アイコン（タスクマネージャーの一覧など）である。

そして**16〜32 px では、256 px 向けに描かれた絵は成立しない**。キーの隙間が 1 px を切って潰れ、青一色の塊になる。これが v1.0.0 で実際に起きたことである（[ADR 0081](v1.0.1/decisions/0081-icon-must-not-depend-on-its-background.md)）。

そこで**トレイが使い切る 32 px までを小マスターが担当する**。境目をここに置くのは、**利用者が拡大率の違うモニター間でウィンドウを動かしたときに絵の形が変わらない**ようにするためである。

| サイズ | どのマスターから焼くか | 主な用途 |
|---|---|---|
| 16 / 20 / 24 / 28 / 32 | **小マスター** | **タスクトレイ（100%〜200% の全域）**、MSIX の小 targetsize |
| 40 / 48 / 256 | **通常マスター** | エクスプローラー、Alt+Tab、ウィンドウの大アイコン、スタートメニューのタイル、Store の掲載画像 |

小マスターが**存在しない場合は通常マスターで代用**され、その旨が生成時に表示される。作らなくてもビルドは通る。

## 3. 生成物と、それを使っている場所

### 生成物

```
assets/png/kbd-enabled-{16,20,24,28,32,40,48,256}.png
assets/png/kbd-disabled-{16,20,24,28,32,40,48,256}.png
assets/kbd.ico              8 面すべてを内包
assets/kbd-disabled.ico     同上
packaging/msix/Assets/      30 枚（Square44x44Logo・Square150x150Logo・StoreLogo の各系列）
```

### 使っている場所

| 使う側 | 使うもの | 何になるか |
|---|---|---|
| `build.rs` | `assets/kbd.ico` → **ordinal 1** | exe 自身のアイコン、トレイの有効時 |
| `build.rs` | `assets/kbd-disabled.ico` → **ordinal 2** | トレイの無効時 |
| `src/gui/win32.rs` | ordinal 1 を `LoadImageW` でサイズ指定 | トレイ・ウィンドウのアイコン |
| `src/tray.rs` | `assets/png/kbd-enabled-16.png` | トレイメニュー先頭の見出しアイコン |
| `examples/egui_ime_probe.rs` | `assets/png/kbd-enabled-32.png` | 検証用 |
| `packaging/msix/build.ps1` | `packaging/msix/Assets/` | Store 掲載・スタートメニュー・タイル |

### `.ico` が 8 面を持つ理由

**`.ico` に無いサイズは Windows が拡縮する。** その拡縮こそが v1.0.0 のアイコンをぼかしていた（[ADR 0080](v1.0.1/decisions/0080-tray-icon-asks-for-the-small-metric.md)）。20 と 28 は v1.0.0 まで欠けていたので、**125% と 175% の利用者だけがぼけた絵を見ていた**。

56 と 64（175%・200% の大アイコン）は入れていない。大アイコンの面は 24 px のトレイ枠ほど拡縮に敏感でなく、フレームは非圧縮なので 64 px 1 面だけで 17 KB 増える。必要になったら `examples/app_icons.rs` の `SIZES` に足せばよい。

## 4. 再生成の手順

```powershell
cargo run --example app_icons     # assets/png/*.png と assets/*.ico
cargo run --example msix_assets   # packaging/msix/Assets/ の 30 枚
cargo build --release             # .ico を exe へ埋め込み直す
```

**必ず 2 つとも流すこと。** 片方だけだと、exe のアイコンと Store のロゴが食い違う。

そのあと、絵が変わったなら受け入れの I 区切り（トレイと設定アプリの見え方）を測り直す。**設定アプリの一覧は行の作成時に撮った PNG を表示するので、既存の行を見ても変わらない** — 手順は [v1.0.1 受け入れチェックリスト §1.1](v1.0.1/03_acceptance-checklist.md) にある。

## 5. Adobe Illustrator での作り方

### 5.1 ドキュメントの設定

新規ドキュメントを次の設定で作る。

| 項目 | 値 | 理由 |
|---|---|---|
| プロファイル | **Web** | 以下が既定で揃う |
| 幅 × 高さ | **16 px × 16 px** | 小マスターの座標系。`viewBox="0 0 16 16"` になる |
| カラーモード | **RGB** | CMYK だと書き出しで色が変わる |
| ラスタライズ効果 | **スクリーン（72 ppi）** | 高解像度だと効果が別の大きさで焼かれる |
| 単位 | **ピクセル** | 環境設定 > 単位 > 一般 |

**アートボードは 16 × 16 のまま**にする。24 で描きたくなるが、`viewBox` が 16 のほうが通常マスターと座標系が揃って比較しやすい。**拡大表示（1600% など）で描けばよい。**

### 5.2 描く前に入れておく設定

- **表示 > ピクセルプレビュー**（`Alt+Ctrl+Y`）を **ON**。実際のドットで見える
- **表示 > ピクセルにスナップ** を **ON**
- **環境設定 > 一般 > 新規オブジェクトをピクセルグリッドに整合** を **ON**
- ウィンドウ > 変形 パネルを出しておく。**X・Y・W・H を数値で直接入れる**（目視で合わせない）

### 5.3 座標の決め方 — ここが品質を決める

**すべての X・Y・W・H を整数にする。** 0.5 が入ると、その辺は 16 px でアンチエイリアスの半透明になり、白いキーが薄く沈む。

さらに、**どのスケールで正確に出るか**は座標の粒度で決まる。

| 座標の粒度（16 単位系） | 拡縮なしで出るサイズ | 半端になるサイズ |
|---|---|---|
| 整数（1 の倍数） | 16、32 | 20、24、28 |
| **偶数（2 の倍数）** ← 推奨 | **16、24、32、40、48** | 20、28 |
| 4 の倍数 | 全部 | なし（ただし 4×4 の粗さになり、キーボードは描けない） |

**偶数に揃えることを勧める。** 100%・150%・200% の 3 つ（利用者の大半）で拡縮ゼロになり、半端になるのは 125% と 175% だけである。

### 5.4 図形のルール

| ルール | 理由 |
|---|---|
| **白い部分は「塗り」で描く。「抜き」にしない** | 複合パスや前面オブジェクトでの型抜きは禁止。背景が透けるため、設定アプリのアクセント色の台座（`#007AD5`）の上で本体と同化して消える（[ADR 0081](v1.0.1/decisions/0081-icon-must-not-depend-on-its-background.md)） |
| **線（ストローク）を使わない。塗りだけ** | ストロークはパスの中心から両側に太るので必ず 0.5 px ずれる。どうしても使ったら **オブジェクト > パス > パスのアウトライン** で塗りに変換する |
| **白の最小は 2 × 2 単位** | 16 px で 2 px。1 単位だと 1 px の筋になり読めない。これが v1.0.0 の失敗である |
| **隙間は 1 単位以上、できれば 2** | 隣り合う白がくっつくと 1 つの塊に見える |
| **角丸は 1〜2 単位まで** | 16 px でそれ以上丸めると円に見える |
| **グラデーション・不透明度・効果（ドロップシャドウ、ぼかし）を使わない** | 16 px では潰れるだけで、`.ico` の非圧縮フレームでは意図しない見え方になる |
| **文字を入れない** | 16 px で読める文字は無い |
| **クリッピングマスクを使わない** | 生成物が読みにくくなり、後から誰も直せない |

### 5.5 色

| 用途 | 値 |
|---|---|
| 有効の本体 | `#0078D4` |
| 無効の本体 | `#8A8886` |
| キー（両方共通） | `#FFFFFF` |

カラーピッカーの **RGB** タブに 16 進で入れる。カラープロファイルは埋め込まない（sRGB 前提）。

**本体の色を明るいほうへ寄せないこと。** `#0078D4` は明るいタスクバー（`#F3F3F3`）に対して約 4.1:1、暗いタスクバー（`#202020`）に対して約 3.6:1 で、図形の基準 3:1 を両方満たしている。明るくすると明るい地で消える。

### 5.6 現行の図形（描き直しの出発点）

通常マスター `kbd-enabled.svg` の座標（16 単位系）:

```
本体      X=1    Y=3    W=14   H=10   角丸 R=1.5
上段キー  Y=5  H=2 : X=2.5  X=5.5  X=8.5  X=11.5   （各 W=2）
下段      Y=9  H=2 : X=2.5 W=2 / X=5.5 W=5 / X=11.5 W=2
```

**この座標は 0.5 を含んでいる**（`2.5`、`5.5`…）。通常マスターは 40 px 以上でしか使わないので実害は無いが、**小マスターでは踏襲しないこと**。§5.3 のとおり偶数へ寄せる。

小マスターは**キーの数を減らして 1 つずつを大きくする**方向で描く。16 px の幅は 14 単位しかないので、上段に 2 単位のキーを 4 つ並べると隙間が 1 単位しか取れない。3 つにすれば 1 つを 3 単位にできる。

### 5.7 書き出し

**ファイル > 別名で保存 > SVG（\*.svg）**。「書き出し > スクリーン用に書き出し」ではなくこちらを使う（設定が細かい）。

ダイアログの設定:

| 項目 | 値 |
|---|---|
| SVG プロファイル | **SVG 1.1** |
| フォント > タイプ | どれでもよい（文字を使わないため） |
| オプション > 画像の場所 | **埋め込み** |
| **詳細オプション > CSS プロパティ** | **プレゼンテーション属性** ← `style="fill:..."` ではなく `fill="..."` で出る |
| 詳細オプション > 小数点以下の桁数 | **1** |
| 詳細オプション > エンコーディング | **UTF-8** |
| **レスポンシブ** | **オフ**（チェックを外す） ← `width` / `height` を残すため |
| Illustrator の編集機能を保持 | **オフ** ← オンだと数十倍に肥大する |

### 5.8 書き出したファイルの確認

テキストエディタで開いて、次を満たしていること。

- 1 行目に `viewBox="0 0 16 16"` と `width="16" height="16"` がある
- 色が `fill="#0078D4"` の形で入っている（`style=` や `class=` になっていない）
- `<path>` が **2 本**（本体・キー）、または本体 1 本 ＋ キーが複数
- **`fill-rule="evenodd"` が無い**（あれば抜きになっている。§5.4 の 1 行目に反する）
- `<image>`、`<clipPath>`、`<filter>`、`<linearGradient>` が無い
- ファイル先頭に Illustrator のコメントブロックが大量に入っていたら「編集機能を保持」がオンだったので、外して出し直す

**ファイル冒頭に、何を意図した図形なのかを HTML コメントで 1 つ書き添える。** 既存の 2 つがそうしている。次に触る人（半年後の自分を含む）が、なぜ抜きではなく塗りなのかを読めるようにするためである。

## 6. 描き替えたあとの手順

1. `assets/svg/` に置く（**生成物のフォルダーではない**）
2. `cargo run --example app_icons`
3. `cargo run --example msix_assets`
4. `cargo build --release`
5. 生成された `assets/png/kbd-enabled-16.png` と `-24.png` を**拡大して見る**。キーが読めるか
6. **アクセント色の台座（`#007AD5`）の上に置いて見る。** 設定アプリの一覧はこの条件である
7. 暗い地（`#202020`）の上でも見る
8. 受け入れの I 区切りを測り直す（[v1.0.1 §1.1](v1.0.1/03_acceptance-checklist.md)）
9. 生成物もコミットする（`assets/png/`、`assets/*.ico`、`packaging/msix/Assets/`）。**リポジトリに resvg を持たない人でもパッケージングできるようにするため**である

## 7. やりがちな失敗

| 失敗 | どうなるか |
|---|---|
| `assets/png/*.png` を手で描いて置く | 次の `app_icons` で消える。`.ico` にも入らない |
| `app_icons` だけ流して `msix_assets` を忘れる | exe のアイコンと Store のロゴが食い違う |
| 白いキーを型抜き（複合パス）で作る | アクセント色の台座の上で絵が消える（[ADR 0081](v1.0.1/decisions/0081-icon-must-not-depend-on-its-background.md)） |
| 0.5 px の座標で描く | 16 px でキーが半透明になり沈む |
| 24 px のアートボードで描いて `viewBox` が 24 になる | 通常マスターと座標系が食い違い、比較できなくなる |
| 描き替えたあと設定アプリの一覧を見て「直っていない」と判断する | 一覧は行の作成時の PNG を表示している。新しい行を作らないと変わらない |
